- **插屏广告广告位改由远端配置下发（纯前端消费改动，无 `/api/**` 接口契约变化）**：
  插屏广告（`front/utils/interstitial-ad.ts`，各页面 `onShow` 调 `maybeShowInterstitial`）
  的 unit-id 原先**硬编码**在 `front/config/interstitial-ad.ts`（首页_插屏 + 日韩_插屏，
  其余页面共用首页_插屏兜底）。现改为读取后端 `app_config`（`cfg_type='display'`，
  见 docs/API.md 八，接口仍是 `GET /api/v1/configs?cfgType=display`）下 `adConfig` 分组的
  新配置项 `interstitialAd`——与同组 `bannerAd` **同构的数组**：
  - **后台需新增配置项**（`cfgType='display'`，分组 `adConfig` 下，与 `bannerAd` 平级）：
    `cfgKey = interstitialAd`，`cfgValue` 为单行 JSON 数组，每项
    `{ "unit-id": "adunit-…", "location": "global", "status": true }`；
    `location` 取 11 个触发位置之一（`global / asia / metals / finance / minute /
    stock-detail / sector-detail / industry-all / us-top100 / news / news-detail`）。
    粘贴用的完整 cfgValue、后台建配置步骤、广告位映射表见
    **`docs/广告位配置-插屏广告.json`**（新增文件，与 `docs/广告位配置-原生模板广告.json` 同规格）。
  - **口径：远端没配置就不展示**——某个 `location` 没有条目 / `status=false` → 该页不弹插屏；
    前端**不做任何本地兜底**（原 `config/interstitial-ad.ts` 里的 `unitId` /
    `unitIdByLocation` 字段已删除）。上下线 / 换广告位全部在后台改配置，无需发版；
    临时下线把 `status` 改 `false` 即可。
  - 解析函数：`front/utils/ad-config.ts resolveInterstitialUnitId(adConfig, location)`
    （纯函数，与 `resolveAdUnitId` 同文件；未配置 / `status=false` / 配置未到达 → 空串）；
    `front/utils/interstitial-ad.ts resolveUnitId` 读 `rootStore.system.configs.adConfig`。
  - **冷启动竞态兜底**：页面 `onShow` 通常早于「登录 + 配置」返回，此时调度器**挂起本次触发**
    （新增 `scheduleConfigWait`，MobX reaction 追踪该 location 解析出的 unit-id），配置到达即
    补一次放行判定（仍走原有闸门：全局单飞 / 微信版本 / 当日次数上限 / 15s 间隔）；
    配置始终没有该 location 或超过 `configWaitTimeoutMs`（默认 8s）则不展示；App 退后台、
    触发页已不是栈顶页时放弃补展示（避免全屏插屏弹在无关页面上）。
  - 类型：`front/types/system.ts` `AdConfig` 新增 `interstitialAd`（条目 interface
    `AdInterstitialConfig`，字段 `unit-id` / `location` / `status`，与 `bannerAd` 一致）
    与 `interstitialConfig`（行为参数，见下条）。
  - **插屏行为参数也一并搬到远端**：`enabled`（总开关）/ `showOnAppForeground`（回前台是否展示）/
    `minIntervalMs`（两次展示最小间隔）/ `newUserWindowDays` + `newUserDailyCap` + `dailyCap`
    （新老用户每日上限）/ `maxAttempts` + `retryIntervalMs`（失败重试）/ `loadTimeoutMs`（加载看门狗）
    / `configWaitTimeoutMs`（冷启动等配置上限）——`front/config/interstitial-ad.ts` 的同名字段
    降级为**默认值 / 兜底**，远端 `adConfig.interstitialConfig`（**对象，字段全部可选**）
    逐项覆盖：解析 `front/utils/ad-config.ts resolveInterstitialSettings(remote, defaults)`
    （纯函数；缺省或类型不合法——字符串 / `null` / `NaN` / `Infinity` / 负数、`maxAttempts<1`
    ——该项回落默认值，`0` 为合法值），调度器每次判定 / 定时器取值时经
    `front/utils/interstitial-ad.ts currentConfig()` 现取，后台改配置即时生效、无需发版。
  - 行为参数（默认值仍在 `front/config/interstitial-ad.ts`）：总开关 / 展示时机 /
    15s 间隔 / 新老用户每日上限（1 / 3）/ 重试 3 次、间隔 1200ms / 看门狗 8s / 等配置 8s。
  - 关联文件（前端）：`front/config/interstitial-ad.ts`、`front/utils/interstitial-ad.ts`、
    `front/utils/ad-config.ts`、`front/types/system.ts`、`front/tests/ad-config.test.ts`、
