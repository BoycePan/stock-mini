## 备注

- **纯前端改动，无 `/api/**` 接口契约变化**：新增**通用弹窗公告组件**
  `front/components/popup-notice`（自管理调度 + 渲染，可复用），首页
  （`pages/global/index`，Tab 首屏）通过行情页工厂 `popupNotice` 选项接入
  「美股市值TOP100」公告（配置在 `front/config/us-top100-notice.ts`，
  无后端依赖，不走 notice 表）。
- 公告 JSON 结构（可序列化为如下 JSON，content 支持 HTML，rich-text 渲染）：

  ```json
  {
    "content": "公告正文（支持 HTML）",
    "path": "/packageQuote/pages/us-top100/index",
    "minVersion": "1.8.6",
    "count": 3
  }
  ```

  - `minVersion`：当前小程序版本 >= minVersion 才展示（`getAppVersion()` +
    `isVersionGte()`，点分数字比较，`front/utils/version.ts`）；
  - `count`：自首次展示当天起连续展示 count 天，**每天最多一次**（wx 本地缓存
    `us_top100_popup_notice_state` 记录 firstShownDate / lastShownDate，
    规则见 `front/utils/popup-notice.ts` 的 `shouldShowPopupNotice`）；
  - `path`：点击「立即查看」/ 卡片跳转的页面路径，空字符串不跳转；
    跳转目标与当前页相同视为「知道了」不重复压栈。
- 弹窗 UI 基于 **tdesign-miniprogram 的 dialog 组件**（居中弹层 `placement="center"`，
  **无底部安全距离**；关闭按钮 / 遮罩 / 按钮交互由 tdesign 处理），正文用 content 插槽
  放 rich-text（支持 HTML），深色主题通过 tdesign CSS 变量（`--td-bg-color-container` /
  `--td-text-color-primary` / `--td-text-color-secondary` / `--td-dialog-close-color`）
  在组件根节点 dark 类下覆盖。主按钮：有 path「立即查看」（跳转），无 path「知道了」（仅关闭）。
- 通用组件用法：`<popup-notice notice="{{ ... }}" storage-key="..." />`——传入
  PopupNotice（content / path / minVersion / count），组件 attached 时自动校验
  minVersion 版本门槛 + count 天每日一次（wx 本地缓存记录日期），命中即弹出；
  content 支持 HTML（rich-text）；path 空则按钮文案「知道了」不跳转，跳转目标为当前页
  视为「知道了」不重复压栈；事件 `bind:close` / `bind:show`。
- 新增埋点：`popup.notice.show`（展示，action）、`popup.notice.tap`
  （点跳转，tap），定义见 `front/config/tracking.ts`。
- 关联文件（前端）：`front/components/popup-notice/*`、
  `front/config/us-top100-notice.ts`、`front/utils/popup-notice.ts`

- **分时页入口开关（纯前端配置消费，无 `/api/**` 接口契约变化）**：跳转
  `packageQuote/pages/minute/index` 前增加开关判定——后台 `app_config`（
  `cfg_type='display'`，见 docs/API.md 八）新增两个配置键：
  - `canShowMinute`：线上正式版（release）读此键；
  - `canShowMinuteDev`：开发版 / 体验版（develop / trial）读此键；
  - 任一为 `false`（或配置未就绪，缺省关闭）则**禁止进入分时页**：行情卡片
    「分时」角标隐藏、点击卡片 / TOP100 列表行提示「分时行情暂未开放」不跳转、
    分享直达分时页的中转（`front/utils/share.ts redirectFromShare`）同样拦截。
  - 解析函数：`front/utils/system-config.ts resolveMinuteEnabled(config, release)`
    （纯函数，模式与 `resolveTop100Enabled` 一致）；类型：
    `front/types/system.ts AppConfig.config` 新增 `canShowMinute` /
    `canShowMinuteDev` 字段。
  - 关联文件（前端）：`front/utils/market-page-factory.ts`（onMetricTap 前置判定 +
    minuteAvailable 角标联动）、`front/packageQuote/pages/us-top100/index.ts`

- **首页弹窗改为服务端驱动（纯前端改动，无 `/api/**` 接口契约变化）**：弹窗公告
  由本地配置改为读取 `notices` 接口 `position='home'` 的公告（`type='notice'`），
  取其 `config`（title / content / path / buttonText / minVersion / count，与
  `PopupNotice` 同构）作为弹窗内容：
  - 映射：`front/utils/popup-notice.ts` 新增 `resolveHomePopupNotice(notices)`
    （取第一条 config 合法的 home 公告，无则返回 null 不弹）；`front/stores/system.store.ts`
    新增 `homePopupNotice` / `homePopupStorageKey` getter。
  - 首页（`pages/global/index`）通过行情页工厂 `popupNotice` / `popupStorageKey`
    响应式 getter 注入（`front/utils/market-page-factory.ts`，store 绑定 computed 字段），
    公告拉取到达时即时出现；`components/popup-notice` 修复 notice 异步到达
    （null → 非空）时补一次调度的问题（原实现空 notice 也会占用「已调度」标记）。
  - 展示状态缓存键按公告 id 区分（`popup_notice_state_{id}`）：换公告 = 换键 =
    重新计天，管理端可随时新建 / 调整公告，无需发版。
  - 删除本地配置 `front/config/us-top100-notice.ts`（不再使用）。
  - 关联文件（前端）：`front/utils/popup-notice.ts`、`front/stores/system.store.ts`、

- **「双环境布尔开关」解析器抽取为可复用工厂（纯前端重构，无 `/api/**` 接口契约变化）**：
  `front/utils/system-config.ts` 由两个重复函数（`resolveTop100Enabled` /
  `resolveMinuteEnabled`）重构为两层结构：
  - `createFeatureToggle(releaseKey)`：工厂，一行生成解析器——线上正式版读
    `<releaseKey>`，开发版 / 体验版读自动推导的 `<releaseKey>Dev`，配置未就绪 /
    键缺省一律 false（缺省关闭），返回纯函数便于单测；
  - `bindToggle(resolver)`：便捷绑定，自动读全局配置 store（`rootStore.system.configs`）
    + 当前运行环境（`isReleaseBuild()`），调用点简化为 `isXxxEnabled()`；
  - 新增开关三步：`types/system.ts` 加一对键 → `createFeatureToggle` 一行 → 需要时
    `bindToggle`。现有 `resolveTop100Enabled` / `resolveMinuteEnabled` 签名不变
    （兼容测试与调用点），并新增便捷版 `isTop100Enabled()` / `isMinuteEnabled()`。
