## 二、修改接口

### POST /api/v1/auth/login

- **变更点**：新增可选入参 `source`，用于区分来源小程序（如 `shiChang-tracker` / `hangQing-tracker`）。
- **入参（新增项）**

  | 参数 | 类型 | 必填 | 说明 |
  |---|---|---|---|
  | source | string | 否 | 来源小程序标识；不传或空白时使用配置的 `app.wechat.default-source`（默认 `shiChang-tracker`，兼容已发布旧小程序，无需发版） |

- **行为变化**：`source` 未在 `app.wechat.apps` 中配置时返回业务码 `400`（`未知的 source`），不会调用微信接口；`openid` 仅在 `(source, openid)` 维度内唯一。
- **出参契约不变**：`{token, expires_in, user}`；`user` 对象新增 `source` 字段（其余字段不变，`openid/unionid/session_key/phone_enc` 仍不外泄）。token 仍为共享同一 `JWT_SECRET` 签发的 HS256 JWT，两小程序 token 全接口通用。
- **关联文件**：`controller/AuthController.java`、`service/AuthService.java`、`service/WechatService.java`、`dao/UserRepository.java`、`model/User.java`、`config/AppProperties.java`（`app.wechat` 配置段）、`application.yml`

## 三、备注

- 多小程序认证兼容：`users` 表新增 `source` 列（`NOT NULL DEFAULT 'shiChang-tracker'`），唯一索引由 `openid` 唯一改为 `(source, openid)` 联合唯一。**线上库需先手动执行 DDL 再发布代码**（本次已执行完毕）。
- `app.wechat` 配置由单 `app-id/app-secret` 改为 `default-source` + `apps` 映射（各来源独立 appid/secret）；新小程序申请后按同格式在 `apps` 下追加并配置环境变量。
- `WechatService.code2Session` 按 `source` 取对应 appid/secret 调微信 `sns/jscode2session`。
- 新增单测 `service/AuthServiceTest`：覆盖 source 缺省走默认、显式透传、未知 source 拒绝、新用户创建、老用户更新登录、空 code 前置校验。
