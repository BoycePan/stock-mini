## 二、修改接口

### 1. 管理端 · 手动触发广告数据拉取（`POST /api/mgr/ad/pull`）出参细化

- **方法 + 路径**：`POST /api/mgr/ad/pull`（原有，本次只改出参结构语义）
- **用途**：手动触发一次数据拉取（先刷 token，再拉广告汇总 + 昨日访问趋势）。本次使广告与访问趋势
  **逐项独立**执行并分别回报：某端广告被跳过/失败不再吞掉同端趋势；未开通流量主不再误报失败。
- **出参**：`ApiResponse<Map>`：`{ from, to, totalRows, failed, sources:[{source, ...}] }`
  - `totalRows`：实际写入行数（广告 + 趋势，跳过/失败项不计）；
  - `failed`：出现真实失败（`adError` 或 `visitError`）的端数——**未开通流量主导致的广告跳过不计入**；
  - `sources[]` 每端字段：
    - `adRows`：广告写入行数（广告成功拉取时存在）
    - `adSkipped`：广告被跳过原因（如 `该端未开通流量主/无广告数据权限，跳过广告拉取`，**非失败**）
    - `adError`：广告真实失败原因（仅真实异常时存在，如 `publisher_adpos_general 返回 ret=45010…`）
    - `visitRows`：访问趋势写入行数（已尝试即存在；微信侧 61503 数据计算中 / 无数据 = 0）
    - `visitError`：访问趋势真实失败原因
    - `error`：任一指标真实失败时的整体提示（`广告: …；趋势: …`，兼容旧字段；未开通流量主不产生）
    - `skipped`：整端跳过（仅当该端未配置 app-secret，原语义不变）
- **鉴权**：不变（`/api/mgr/**`，`MgrAuthInterceptor` Bearer admin token）。

## 备注

- **未开通流量主的端自动跳过广告拉取**：`publisher/stat`（`action=publisher_adpos_general`）对未开通流量主
  的小程序返回 `base_resp.ret=-1` 且 `err_msg` 为空（2026-09-04 对 hangQing-tracker 实测复现，
  属账号侧权限拒绝而非系统繁忙），另兼容官方文档「无效流量主」错误码 `2009 / 1807`。
  命中时 `WxAdService` 记 INFO 并跳过该端广告（返回 0 行、不抛异常）：
  - 定时任务 `PullWxAdDataTask`：不再每 20 分钟对未开通端刷 ERROR 日志；
  - 手动拉取：以 `adSkipped` 回报，且该端**访问趋势照常拉取**。
  - 待该端在对应小程序后台开通流量主并完成结算协议后，自动恢复拉取，无需改配置/代码。
- 关联文件（后端）：
  - `service/WxAdService.java`（判定 + `AdPullResult` 细分 + `manualPullAll` 解耦）
  - `task/PullWxAdDataTask.java`（仅注释）
  - `service/WxAdServiceTest.java`（新增单测：ret=-1 空 err_msg / 2009 跳过、真实错误仍抛、成功落库、手动拉取解耦）
- 关联文件（管理端 UI）：`code/frontend/wx-stock-manage` `AdsPage.tsx` / `VisitPage.tsx` / `types/api.ts`
  （拉取结果提示区分「广告跳过（未开通流量主）/ 广告失败 / 趋势失败」，不再误显示「广告0条」）。
