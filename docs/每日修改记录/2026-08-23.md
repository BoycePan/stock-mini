## 一、新增接口

### POST /api/v1/track/events

- **用途**：用户行为打点批量上报。前端埋点 SDK 攒批提交（进页面 / 点击 / 搜索 / 切主题 / 分享等），
  服务端按 `event_id` 幂等去重后落 `click_event` 表。
- **鉴权**：可选鉴权（OptionalAuthInterceptor）。携带有效 `Authorization: Bearer <token>` 时解析
  `user_id`；未携带 / 无效也放行，`user_id` 记 null（匿名行为）。
- **入参**（JSON body）

  | 参数 | 类型 | 必填 | 说明 |
  |---|---|---|---|
  | events | array | 是 | 事件数组，单批 ≤ 100（默认，可配 `app.tracking.max-batch-size`；超出返回 400） |

  `events` 元素：`eventId`（必填，幂等键）、`eventName`（必填，点分事件名）、`eventType`、`page`、
  `target`、`props`（object）、`durationMs`、`sessionId`、`clientTs`、`platform`、`appVersion`。
  详见 `docs/API.md`「七、用户行为打点」。

- **出参**：`data` 为统计对象

  | 字段 | 说明 |
  |---|---|---|
  | accepted | 实际新入库条数 |
  | duplicated | event_id 冲突被幂等跳过的条数 |
  | invalid | 缺 eventId / eventName 被丢弃的条数 |

- **关联文件**：`controller/TrackController.java`、`service/TrackService.java`、
  `dao/TrackRepository.java`、`model/TrackEvent.java`、`model/ClickEvent.java`、
  `config/OptionalAuthInterceptor.java`、`config/WebConfig.java`、`config/AppProperties.java`
  （`app.tracking` 段）、`application.yml`、`scripts/click_event.sql`、`src/test/resources/schema.sql`

## 三、备注

- 新增 `click_event` 表（用户点击/行为打点），DDL 见 `scripts/click_event.sql`；幂等去重靠
  `event_id` 唯一索引 + `ON CONFLICT (event_id) DO NOTHING`。生产库需先执行该脚本再发布代码。
- 新增 `OptionalAuthInterceptor`：与 `AuthInterceptor`（强制鉴权）不同，token 缺失/无效时照常放行，
  只做「尽力而为」的 `user_id` 解析，用于打点上报等允许匿名的接口。
- 前端埋点 SDK 与事件命名规范见 `docs/埋点打点方案.md`（前端代码由他人实现，本仓库本轮只改后端）。
- `application.yml` 的 HikariCP 增加 `connection-init-sql: SET timezone TO 'Asia/Shanghai'`：
  数据库服务器 `timezone` 为 UTC，`now()` / `CURRENT_TIMESTAMP` 会返回 UTC 时间，与 DAO 用
  `LocalDateTime.now()`（JVM 已钉 Asia/Shanghai）写入的无时区 TIMESTAMP 列口径不一致。
  此处让每个连接初始化时把会话时区钉死为东 8 区，保证 TIMESTAMPTZ 显示与既有 TIMESTAMP 列一致。
  （生产库建议再执行 `ALTER DATABASE gu_yu_stock SET timezone TO 'Asia/Shanghai';` 一劳永逸。）
