## 1. 背景与目标

### 1.1 现状

- 小程序当前 TabBar 五个页：**全球 / 日韩 / 有色 / 财经 / 设置**（`front/app.json`，自定义 tabbar，微信上限 5 个，无法再加第 6 个）。
- 行情类页面（全球/日韩/有色）数据**前端直连外部接口**（腾讯/新浪/东财），不走后端（见 `front/README.md`「数据策略」）；财经新闻、搜索、个股/板块详情走后端接口。
- 后端为 Spring Boot（`backend-java/`），已有外部数据抓取模式（`EastmoneyKlineClient` + `DataSource` 限流/重试）与 Caffeine 缓存依赖。
- 前端已积累的基金相关调研：`docs/天天基金限购金额接口调研.md`（限购金额数据源）、`docs/魔方板块分析/魔方板块-接口文档.md`（基金持仓/搜索/净值等抓包整理）。

### 1.2 目标

新增**基金板块**，包含两级页面：

| 页面 | 内容 |
|------|------|
| 基金列表页 | 基金名称、最新净值、**日涨跌幅**、申购状态、**限购额度**（是否限购/具体限额） |
| 基金详情页 | 基本信息（类型/风险等级/公司/成立日期）、**限购详情**（申购状态/最低申购/当日累计限额/是否可买）、**成分股**（股票代码/简称/占比/较上期变动/所属行业）、**行业配置**（证监会行业占比/同类平均）、净值走势图（可选） |

## 2. 需求拆解

### 2.1 列表页字段

| 字段 | 来源接口 | 说明 |
|------|---------|------|
| 基金代码/名称 | 任意列表接口 | |
| 最新单位净值 | t=8 `[3]` / 单查 `DWJZ` / 新浪 f_ `[1]` | |
| 日涨跌幅 | t=1 `[8]` / 单查 `RZDF` / 新浪 f_ 计算 | **t=8 无涨跌幅**（见 4.1） |
| 申购状态 | t=8 `[5]` / t=1 `[9]` / 单查 `SGZT` | 开放申购 / 限大额 / 暂停申购 |
| 限购额度 | t=8 `[9]` / 单查 `MAXSG` | 具体金额；不限购为超大默认值（≥1e10） |

### 2.2 详情页字段

| 区块 | 字段 | 来源接口 |
|------|------|---------|
| 基本信息 | 名称/类型/净值/累计净值/日涨幅/风险等级/基金公司/成立日期/跟踪指数 | `FundMNNBasicInformation` |
| 限购详情 | 申购状态/赎回状态/最低申购金额/**当日累计申购限额**/是否可买 | `FundMNNBasicInformation` |
| 成分股 | 股票代码/简称/占净值比例/较上期变动（增持/减持/新进）/所属行业 | `FundMNInverstPosition`（JSON） |

| 净值走势（可选） | 单位净值时间序列（含每期收益） | `pingzhongdata/{code}.js` → `Data_netWorthTrend` |
| 季度持仓明细（可选） | 季度股票/债券投资明细（截止日期） | `FundArchivesDatas.aspx?type=jjcc/zqcc`（HTML） |

## 4. 接口明细（请求/响应/字段）

### 4.1 接口一: `Fund_JJJZ_Data.aspx` t=8 —— 全量列表（限额/状态/净值）

**请求**

```
GET https://fund.eastmoney.com/Data/Fund_JJJZ_Data.aspx?t=8&page=1,50000&js=reData&sort=fcode,asc
```

| 参数 | 必填 | 说明 | 示例 |
|------|:---:|------|------|
| `t` | 是 | 数据模式。**t=8** = 净值+申购状态+限额；t=1 = 常规列表（含涨跌幅，无限额） | `8` |
| `page` | 否 | `start,count`，count 最大 50000（全市场约 2.7 万只） | `1,50000` |
| `js` | 否 | 返回 JS 变量名 | `reData` |
| `sort` | 否 | 排序，如 `fcode,asc` / `zdf,desc` | `fcode,asc` |
| `text` | 否 | 名称/代码搜索，**仅 t=1 生效，t=8 下被忽略** | - |

注意事项：
- 建议携带浏览器 UA；全量响应约 2MB+（27,367 只，实测 2026-08-28）。
- 不带 `page` 时默认返回 100 条；`record` 字段为全市场总数。
- 未携带 `page` 与指定 `page=1,count` 行为一致，count 决定返回条数。

**响应**（`js=reData` 时为 JS 变量，去掉 `var reData=` 前缀后是合法 JSON）

```js
var reData={
  datas: [
    ["000001","华夏成长混合","混合型-灵活","1.3400","08-27","开放申购","开放赎回","","10.0","100000000000","1.0","1","0.15%"],
    ...
  ],
  record: "27367",        // 全市场基金总数
  pages: "9121",          // 总页数（按 3 条/页口径）
  curpage: "1",
  showday: ["2026-08-27","2026-08-26"]  // 净值日期
}
```

**datas[i] 字段位置表（13 列）**

| 索引 | 含义 | 示例 |
|------|------|------|
| [0] | 基金代码 | `000001` |
| [1] | 基金名称 | `华夏成长混合` |
| [2] | 基金类型 | `混合型-灵活` |
| [3] | 单位净值 | `1.3400` |
| [4] | 净值日期(MM-DD) | `08-27` |
| [5] | 申购状态 | `开放申购` / `限大额` / `暂停申购` |
| [6] | 赎回状态 | `开放赎回` |
| [7] | 下次开放日期 | ``（空） |
| [8] | 最低申购金额 | `10.0` |
| [9] | **当日累计申购限额** | 限购=`10.0`；不限购=`100000000000` |
| [10] | 手续费率 | `1.0` |
| [11] | 购买状态码（1=可买） | `1` |
| [12] | 费率文案 | `0.15%` |

> ⚠️ **t=8 没有涨跌幅字段**（只有单位净值，无前收净值，无法计算日涨跌）。

### 4.2 接口二: `Fund_JJJZ_Data.aspx` t=1 —— 列表（涨跌幅/状态）

**请求**

```
GET https://fund.eastmoney.com/Data/Fund_JJJZ_Data.aspx?t=1&js=reData&text=000001&page=1,1
```

**响应**

```js
var reData={chars:[...],
  datas:[["000001","华夏成长混合","HXCZHH","1.34","3.913","1.306","3.879","0.034","2.60",
          "开放申购","开放赎回","","1","0","1","","1","0.15%","0.15%","1","1.50%"]],
  count:["1","1","0","0"], record:"1", pages:"1", curpage:"1",
  indexsy:[1.13,0.86,1.50,], showday:["2026-08-27","2026-08-26"]}
```

**datas[i] 字段位置表（21 列，与单查接口交叉校验）**

| 索引 | 含义 | 示例（000001） |
|------|------|------|
| [0] | 基金代码 | `000001` |
| [1] | 基金名称 | `华夏成长混合` |
| [2] | 拼音缩写 | `HXCZHH` |
| [3] | 单位净值（最新） | `1.34` |
| [4] | 累计净值 | `3.913` |
| [5] | 昨日单位净值 | `1.306` |
| [6] | 昨日累计净值 | `3.879` |
| [7] | 日增长值 | `0.034`（= [3]-[5]） |
| [8] | **日增长率%** | `2.60`（与单查 `RZDF` 一致） |
| [9] | 申购状态 | `开放申购` |
| [10] | 赎回状态 | `开放赎回` |
| [11] | 下次开放日期 | ``（空） |
| [12] | 购买状态码（1=可买） | `1` |
| [17] | 申购费率 | `0.15%` |
| [18] | 折后费率 | `0.15%` |

> ✅ `text` 参数在 t=1 下**支持名称/代码搜索**（实测 `text=华夏成长` 模糊匹配、`text=000834` 精确返回 1 条）。

### 4.5 接口五: `FundArchivesDatas.aspx?type=hypzsy` —— 行业配置（HTML 片段）

**请求**

```
GET https://fund.eastmoney.com/F10/FundArchivesDatas.aspx?type=hypzsy&code=000001&rt=1787xxxxxx
```

| 参数 | 必填 | 说明 |
|------|:---:|------|
| `type` | 是 | **`hypzsy`**（行业配置）。注意不是 `hypz`（实测 `hypz` 返回空/404） |
| `code` | 是 | 6 位基金代码 |
| `rt` | 否 | 时间戳防缓存 |

**响应**（`var apidata={content:"<table>…"}`，HTML 片段）

```js
var apidata={ content:"<table class='w782 comm hypz'><thead><tr><th class='first'>证监会行业代码</th><th>行业名称</th><th>基金行业配置</th><th>同类平均</th><th class='last'>比同类配置</th></tr></thead><tbody>
<tr><td>A</td><td class='tol'>农、林、牧、渔业</td><td class='tor'>---</td><td class='tor'>1.74%</td><td class='tor'>-1.74%</td></tr>
<tr><td>B</td><td class='tol'>采矿业</td><td class='tor'>0.00%</td><td class='tor'>3.51%</td><td class='tor'>-3.51%</td></tr>
<tr><td>C</td><td class='tol'>制造业</td><td class='tor'>72.78%</td><td class='tor'>50.59%</td><td class='tor'>22.19%</td></tr>
…（A~S 共 19 个证监会行业 + ZZZ 合计行）…
<tr><td>ZZZ</td><td class='tol'>合计</td><td class='tor'>79.98%</td><td class='tor'>63.91%</td>…</tr>
</tbody></table>", arryear:[...], curyear:0}
```

**解析要点**
- 外层是 JS 变量，key 未加引号（`content` 等），**不是严格 JSON**，不能直接 `JSON.parse`；需正则抽取 `content:"…"` 或先转义 key。
- `content` 内是 HTML 表格：`td` 依次为 行业代码 / 行业名称 / 基金行业配置 / 同类平均 / 比同类配置。
- 未持有的行业配置显示 `---`（如制造业 72.78%，农、林、牧、渔业 `---`）。
- 实测 000001：制造业 72.78%（同类平均 50.59%）、信息传输 7.18%、合计 79.98%。
- 行业配置为**季度数据**（最新 2026-06-30），QDII 基金可能无数据。

### 4.6 接口六: `FundArchivesDatas.aspx?type=jjcc/zqcc` —— 季度持仓明细（HTML 片段）

**请求**

```
GET https://fund.eastmoney.com/F10/FundArchivesDatas.aspx?type=jjcc&code=000001&topline=10&year=2026
GET https://fund.eastmoney.com/F10/FundArchivesDatas.aspx?type=zqcc&code=000001&year=2026
```

| 参数 | 必填 | 说明 |
|------|:---:|------|
| `type` | 是 | `jjcc`=股票持仓明细、`zqcc`=债券持仓明细 |
| `code` | 是 | 6 位基金代码 |
| `topline` | 否 | 返回前 N 条（默认全部） |
| `year` | 否 | 年度 |

## 5. 限购判断口径

综合《天天基金限购金额接口调研.md》与本次实测：

1. **不限购**：`MAXSG` / `datas[i][9]` 为超大默认值（`100000000000`、`10000000000` 等，**≥ 1e10 视为无限制**）。
2. **限大额**：状态为"限大额"，限额为具体值（如 270042 = 5 元、000834 = 10 元、001240 = 1000 万）。
3. **暂停申购**：状态为"暂停申购"、`ISBUY=4`；**当日累计限额为 0，或限额 < 最低申购金额时，归一化为"暂停申购"**。
4. **判断优先级**：先看状态码/文案，再看限额数值。
   - 实测反例：`000005`（嘉实增强信用）状态=暂停申购但 `[9]=1e11`；`000044`（嘉实美国成长美元现汇）状态=暂停申购且 `[9]=0.01 < 最低申购 10`。**不能只看限额数值判断状态**。
5. 列表展示建议：限额 ≥ 1e10 → 展示"不限购/可申购"；限额 < 1e10 且状态=限大额 → 展示"限购 X 元"；状态=暂停申购 → 展示"暂停申购"。

## 6. 列表页数据方案（三种方案对比）

### 方案 A：精选配置列表（推荐，契合现有产品形态）

**思路**：在 `front/config/fund.ts` 配置 20~50 只代表性基金（纳指/标普/黄金/医药/消费等主题），**前端直连 `FundMNNBasicInformation` 按只查询**，一个接口拿全 涨跌(`RZDF`) + 限额(`MAXSG`) + 净值(`DWJZ`) + 状态(`SGZT`)。

**请求方式**：列表页加载时对 N 只基金并发发起 N 次轻量 GET（单次响应 ~1KB，可并发 10~20 个，分批）。

**前端代码结构**（遵循现有模式）：
- `config/fund.ts`：基金标的配置（code / name / theme），类似 `config/tabbar.ts` 的 `MACRO_ASSETS`；
- `api/fund.ts`：单接口封装（失败降级为空数据，不抛错），类似 `api/quote.ts`；
- `pages/fund/index`：列表页。

**优点**：
- 前端直连、**零后端改动**；接口是 JSON，解析简单；
- 与现有"配置化标的 + 批量拉取"的产品形态完全一致；
- 域名白名单只需加 1 个：`fundmobapi.eastmoney.com`。

**缺点**：
- 只能覆盖配置的几十只基金，无全市场浏览/搜索/筛选；
- 列表规模受限于并发请求数（每只 1 次请求）。

**工作量**：小（前端 ~2 个文件 + 1 个页面 + 白名单）。

---

### 方案 B：全市场列表（后端合并 t=8 + t=1）

**思路**：后端定时拉取 `t=8`（限额/状态/净值）与 `t=1`（涨跌幅/状态）两份全量（各 ~2MB），**按 fcode 合并**后提供 REST 接口；前端调自己的后端。

**后端接口设计（草案）**

```
GET /api/v1/fund/list?sort=zdf,desc&limit=100&offset=0&status=limit|paused|all&keyword=xxx
```

| 参数 | 说明 |
|------|------|
| `sort` | 排序：`zdf,desc`（涨跌幅）/ `fcode,asc` |
| `status` | 过滤：`all` / `limit`（限大额）/ `paused`（暂停申购） |
| `keyword` | 名称/代码关键字（本地过滤） |

响应：`{ items: [{ code, name, type, nav, navDate, zdf, sgzt, minsg, maxsg, buyable }], total }`

**合并/缓存策略**：
- 后端缓存两份全量（Caffeine，建议 TTL 30~60 分钟），避免每次请求都拉 2MB；
- 净值数据更新时点：交易日 15:00 后陆续更新，21:00 前基本齐；可在 16:00 / 20:00 各刷新一次；
- 合并：以 t=8 为准（限额/状态/净值），用 t=1 补 `涨跌幅`（`[8]`）与 `日增长值`（`[7]`）；
- 合并失败容错：t=1 缺某只 → 涨跌幅置 null（页面显示 "--"）。

**优点**：
- 全市场数据、支持排序/筛选/搜索，体验最完整；
- 前端永远只调自己后端，无解析风险、可缓存。

**缺点**：
- 需要后端开发（抓取 + 合并 + 接口 + 缓存调度）；
- 全量响应大，抓取频率受限（东财非官方接口，不宜高频率）；
- 全量 2.7 万只对小程序列表意义有限（用户不会翻 2.7 万只）。

**工作量**：中~大（后端 1 个抓取服务 + 1 个接口 + 缓存，前端列表页）。

---

### 方案 C：折中（t=1 全量主列表 + 限大额补查限额）

**思路**：后端拉 `t=1` 全量做列表主数据（涨跌幅/状态文案/净值，~1.5MB），前端列表展示"限大额/暂停申购"状态标识；对少数状态为"限大额"的基金，用 `FundMNNBasicInformation` 补查具体 `MAXSG`（全市场限大额基金数量有限，补查成本低）。

**后端接口设计（草案）**

```
GET /api/v1/fund/list?sort=zdf,desc&limit=100      // 列表（含状态标识，限额为空）
GET /api/v1/fund/limit?codes=000834,270042,...      // 批量补查限额（内部并发调单查接口）
```

**优点**：
- 比方案 B 轻（只拉一份全量 + 按需补查）；"是否限购"的标识对绝大多数用户已够用；
- 具体限额只在点进详情/少数限大额基金时展示。

**缺点**：
- 仍需后端开发；列表接口含两个阶段的数据（主列表 + 补查限额）；
- "不限购"的基金无法展示具体限额（也不需要展示）。

**工作量**：中。

---

### 对比总表

| 维度 | 方案 A（精选直连） | 方案 B（全市场合并） | 方案 C（折中） |
|------|:---:|:---:|:---:|
| 覆盖范围 | 配置的几十只 | 全市场 2.7 万只 | 全市场（限额仅限大额基金） |
| 涨跌 + 限额齐全 | ✅ 单接口全有 | ✅ 合并后全有 | ⚠️ 限额需补查 |
| 前端解析复杂度 | 低（JSON） | 低（自己后端） | 低 |
| 后端开发量 | **零** | 大 | 中 |
| 列表请求量 | N 次轻量单查 | 1 次全量（后端缓存） | 1 次全量 + 少量补查 |
| 域名白名单 | +1 个（fundmobapi） | +1 个（fund.eastmoney.com，若后端拉则不加） | 同左 |
| 适合场景 | 快速上线、精选展示 | 完整基金超市 | 折中 |

**建议**：先做**方案 A** 快速验证产品形态；如用户反馈需要全市场浏览/搜索，再升级**方案 C → B**（后端合并逻辑可复用）。

## 7. 详情页数据方案

详情页数据来源组合（点击列表项进入）：

| 区块 | 数据 | 接口 | 调用方 |
|------|------|------|--------|
| 基本信息 + 限购详情 | `FundMNNBasicInformation` | JSON | 前端直连（方案 A 场景）/ 后端（方案 B/C 场景） |
| 成分股 | `FundMNInverstPosition` | JSON | 前端直连 |
| 行业配置 | `FundArchivesDatas.aspx?type=hypzsy` | **HTML 片段** | **建议后端适配成 JSON** |
| 净值走势（可选） | `pingzhongdata/{code}.js` `Data_netWorthTrend` | JS 变量 | 前端直连（去前缀后 JSON.parse） |

### 7.1 行业配置（HTML）的两种接入方式

**方式 1（推荐）：后端适配**
- 后端新增 `GET /api/v1/fund/industry?code=000001`；
- 后端抓 `type=hypzsy` → 正则抽 `content` → 解析表格（后端可用正则或引入 JSoup）→ 输出 JSON：
  ```json
  { "code":"000001", "quarter":"2026-06-30",
    "items":[ {"industryCode":"C","name":"制造业","ratio":72.78,"avg":50.59,"diff":22.19}, … ],
    "total": 79.98 }
  ```
- 前端零解析、可缓存（季度数据 TTL 可到 24h）。

**方式 2：前端直连解析（不推荐）**
- 前端 `wx.request` 拿 HTML 文本（`dataType:'text'`，实测 `charset=utf-8` 不乱码）；
- 但小程序无 DOM 且不能用 `eval`，只能正则抽 `content` + 正则解析 `<tr><td>`；
- 结构一变（列顺序/class 调整）即挂，且无缓存（每个用户每次进详情都重新解析）。

> 结论：**JSON 类接口（限购/成分股/净值走势）前端直连没问题；HTML 类接口（行业配置）走后端适配成 JSON**，这是本方案的核心分层原则。

### 7.2 净值走势解析

`Data_netWorthTrend` 去 `var ` 前缀后是合法 JSON 数组，可直接 `JSON.parse`；取 `{x: 时间戳ms, y: 净值}` 序列画折线（小程序端用 `ec-canvas` 或轻量 canvas）。

## 10. 风险与注意事项

1. **非官方公开接口**：以上均为天天基金/东方财富非官方接口，字段/结构可能随时变动，解析必须容错（异常时降级为空数据，参考 `api/quote.ts` 的失败降级模式）。
2. **HTML 解析脆弱**：`hypzsy`/`jjcc` 为 HTML 片段且外层是 JS 变量（非严格 JSON），结构变动即失效；建议后端解析并做结构校验。
3. **频率限制**：全量接口响应大（~2MB），不宜高频率抓取；后端需限流（参考 `DataSource`）+ 缓存（Caffeine）。
4. **Referer 限制**：新浪源（`hq.sinajs.cn`）需 Referer 且小程序端**无法自定义**（`front/README.md` 已有教训）；东财 fund 接口实测无需 Referer。
5. **编码**：东财 fund 接口实测 `charset=utf-8`；新浪为 GB18030（后端需转码）。
6. **涨跌幅与限额不在同一接口**：t=8 无涨跌幅、t=1 无限额——列表方案必须先定（见第 6 节）。
7. **数据更新时点**：基金净值交易日 15:00 后更新，QDII 滞后 1~2 天（如 000834 净值日期 08-26）；行情页需容忍"净值日期非当日"。
8. **状态判断陷阱**：暂停申购的基金限额字段可能是 1e11 或极小值，**判断必须状态+限额结合**（见第 5 节）。
9. **成分股/行业配置为季度数据**：最新为 2026-06-30 季报，QDII 可能无行业配置数据。
10. **t=1 净值对字段对净值滞后基金可能错位/为空**（如 000834），以 `FundMNNBasicInformation` 为准。
