# tabbar 行情页卡片报价 ↔ 分时图页数据源映射（核查）

> 核查时间：2026-09-17 21:24 CST；核查范围：`pages/{global,asia,metals,finance}` 五个 tabbar 页
> （设置页无行情）与 `packageQuote/pages/minute`（分时图页，含「分时 TAB」）。
> 结论一句话：**两页不是同一套取数链**——tabbar 页是「多源共识聚合」，分时页是「每 code 可配的源优先级 + 逐源兜底」，
> 只有「双方都落在东财同一 secid」的卡片才是真同源，其余是**同标的异源**，另有个别卡片是**标的错位**。
>
> ⚠️ **2026-09-17 改造后本文档不变的部分**：卡片侧（tabbar 页）取数链完全未动，上文下文的「卡片报价取数」列仍然准确；
> **变了的部分**：分时页的取数顺序改为**可配置**——`config/minute.ts` 的 `priority`（分时序列，缺省
> 腾讯分时 → 东财分时 → Yahoo）与 `quotePriority`（基础信息报价，缺省 腾讯快照 qt.gtimg.cn → 东财 ulist），
> 实施细节见 [`minute-api.md` §2.1](./minute-api.md)。因此下表中「分时取数」列描述的是**该 code 能用到的源及其标识**，
> 实际顺序以配置为准（腾讯无覆盖的标的，东财仍是唯一/首选源）。

## 一、两页的取数架构（这是"不同源"的根因）

| | tabbar 行情页 | 分时图页 |
| --- | --- | --- |
| 入口 | `api/market.ts`（`getGlobalMarketPage` / `getAsiaMarketPage` / `getMetalsMarketPage` / `getFinanceMarketPage`） | `utils/minute.ts` `fetchMinuteData(code)` |
| 配置 | `config/tabbar.ts`（`sources` / `aKeys` / `usKeys` / `tc` / `emSecid` / `sinaKey`） | `config/minute.ts` `MINUTE_SOURCES`（`em` / `tc` / `yahoo` / `emProxies` / `emCross`） |
| 取数方式 | ① `fetchAccurate` 多源**共识聚合**（按优先级排序、相似报价取中位数）② 页面专链的「优先源 + 兜底源」（新浪优先/东财优先/preferEm） | 展开 `resolveMinutePlan` 后按配置的**源优先级从前到后**尝试（缺省 腾讯分时 → 东财 trends2 → Yahoo），失败/点数不足自动切下一个源（5 分钟源级熔断） |
| 接口族 | 腾讯 `qt.gtimg.cn`、新浪 `hq.sinajs.cn`、东财 `push2delay.eastmoney.com`（`stock/get`、`ulist.np/get`、`clist/get`）、金投网 `api.jijinhao.com`、后端 `/api/news/feed` | 东财 `push2delay…/api/qt/stock/trends2/get`、腾讯 `web.ifzq.gtimg.cn/appstock/app/minute/query`、Yahoo `query1.finance.yahoo.com/v8/finance/chart` |
| 基础信息 | —（卡片本身就是一行报价） | 按 `quotePriority` 并发取数（缺省 **腾讯快照 qt.gtimg.cn** → 东财 ulist.np/get），失配时回退分时推算 |

要点：

1. 同一标的「腾讯报价 ↔ 东财分时」或「新浪报价 ↔ 东财分时」都**不是**同一个源，只是同一个标的；
2. 只有卡片走 `em_ulist`（东财 ulist）或 `em`（东财 stock/get）**且 secid 与 `MINUTE_SOURCES[code].em` 完全一致**时，才是真同源；
3. 分时页自 2026-09-17 起是**每 code 可配的源优先级**（缺省「腾讯分时 → 东财 trends2 → Yahoo」）：
   有腾讯代码且腾讯能给出有效多点的标的（A股/港股）走腾讯（与卡片报价同为腾讯系，实测值一致），
   腾讯不覆盖或只返回 1 点的标的（期货/商品/外汇/板块/日韩/美股）自动落东财；
4. 卡片侧则常见「新浪优先 / 腾讯优先 / 东财优先」混用，因此**同一标的的卡片与分时仍可能是不同第三方**，
   下文「同源」列判断的是「是否同一接口族 + 同一 secid」，不是「数值是否一致」。

| 域 / 路径 | 用途 | 实测结果 |

| `https://web.ifzq.gtimg.cn/appstock/app/usfqkline/get?param=usAAPL.OQ,day,,,320,qfq` | **美股日/周/月 K**（个股 `usAAPL.OQ`、指数 `usDJI`/`usINX`/`usIXIC`） | ✅ 200 |

| `https://web.ifzq.gtimg.cn/appstock/app/kline/mkline?param=sh600519,m1,,320` | 分钟 K | ⚠️ 301 → `web3.ifzq.gtimg.cn`（**又换一个域**，需单独加白名单） |

1. **`qt.gtimg.cn` 只有实时快照**，`/appstock/**` 路径在该域一律 `bad request`；
2. 腾讯侧的**分时**与**日K**是两个**不同域上的不同端点**（`web.ifzq.gtimg.cn` 的 `appstock/app/minute/query`
   与 `appstock/app/{,us}fqkline/get`、`kline/kline`），`data.gtimg.cn` 的 flashdata 系已在 2021/2022 停更、不可用；
3. 所以「卡片（腾讯快照）与分时（腾讯分时）」**不可能通过换域做到同源**，只能保证同标的；
   真要同源，得让两边都落到东财同一 secid（见第四节建议）；
4. 小程序合法域名现状：`qt.gtimg.cn`（报价）、`web.ifzq.gtimg.cn`（腾讯分时 + 腾讯 K 线）已在白名单；
   `proxy.finance.qq.com`、`web3.ifzq.gtimg.cn`、`data.gtimg.cn` 若要启用需在微信公众平台新增。
