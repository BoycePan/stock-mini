# 微信广告数据每日拉取 · 分析与建表方案（PullWxAdDataTask）

> 状态：✅ 接口已实测可用（2026-09-02 用真实 token 验证 `publisher_adpos_general` 返回 `ret:0`），方案定稿，按此实施。
> 关联代码：`backend-java/src/main/java/com/guyu/stock/task/PullWxAdDataTask.java`（当前为空壳骨架）。
> 范围：广告数据只存一张表 `wx_ad_daily_stat`（拉取量 / 曝光 / 点击 / 收入等指标）；另加一张 `wx_access_token` 存接口凭证，由独立任务定时刷新。不建日志表、广告单元字典、结算表。
> 本文档只做分析与建表草案；按仓库规则，后续写 `backend-java/` 需用户放行，涉及对外 `/api/**` 变更需记入 `docs/每日修改记录/`。

## 〇、实测结论（2026-09-02）

- ✅ 老接口 `publisher/stat`（路线 A）**可用**：`action=publisher_adpos_general` 返回 `ret:0` 且有数据，字段齐全（拉取/曝光/点击/income 分/ecpm 分千次）。
- ✅ `get_adunit_list` 可用，返回 7 个原生模板广告单元（首页/财经/美股Top100/有色/日韩/分时页-首页进入/财经详情页）+ 封面广告，均 `AD_UNIT_STATUS_ON`。
- ⚠️ **当前实际产生广告数据的只有「封面广告」`SLOT_ID_WEAPP_COVER`**（近 7 天汇总接口只回封面，有曝光/点击/收入）；7 个原生模板广告位在汇总里无数据，`publisher_adunit_general` 细分接口也返回 `total_num:0`。
- ⚠️ 数据仅保留**近几天**（拉 30 天前区间 `total_num:0`）→ 必须每日持续拉取，漏跑无法补历史。
- 结论：**按「广告位类型」存**（不区分广告单元），封面/激励视频/插屏等任何类型都落，未来开新广告位自动入表。

## 一、需求口径

小程序端内嵌了微信**原生模板广告**（`front/components/ad-banner`，`<ad-custom>`，location：`homeTop / asiaTop / matalsTop / finance / minute-detail / finance-detail / us-top100`，配置来自 `app_config` 的 `adConfig.bannerAd`），属于**小程序流量主（广告变现）**。

「每日拉取微信的广告展示信息」= 拉取**微信侧统计的广告数据**，本方案只落这些指标：

- 拉取量（请求成功数 `req_succ_count`）
- 曝光量、曝光率
- 点击量、点击率
- 分账收入（单位：**分**）、千次曝光收益 ecpm（单位：**分/千次**）

维度仅保留**广告位类型 × 统计日**（`SLOT_ID_WEAPP_*`），一行 = 一端 × 一种广告位类型 × 一天。
不落广告单元级细分、结算对账、任务日志——这些以后需要再加表。

## 二、前置条件（决定成败的账号侧事实）

| # | 前置条件 | 如何确认 | 若缺失 |
|---|---|---|---|
| 1 | 小程序已**开通流量主** | 小程序后台 → 推广/流量主 | 接口报 `1807 / 2009 无效流量主` |
| 2 | 已签署**结算协议** | 流量主 → 财务管理/协议 | 接口报 `1735 商户未完成协议签署流程` |
| 3 | 具备 appid/secret | `backend-java` 配置 `app.wechat.apps.<source>`（默认 `shiChang-tracker`） | 无法换取 access_token |

## 三、要调哪些接口

### 3.0 凭证接口（必调）与 token 落库

```
GET https://api.weixin.qq.com/cgi-bin/token
    ?grant_type=client_credential&appid=APPID&secret=APPSECRET
→ { "access_token": "...", "expires_in": 7200 }
```

**token 存表、独立任务定时刷新**（不放在拉广告数据的任务里）：

- 每端（source）一行，存 token + 过期时间；
- 独立任务 `RefreshWxAccessTokenTask` 定时刷新：在 token 过期前提前刷新（微信有效期 7200s，建议每 100 分钟刷新一次，或用 `expires_at` 判断「剩余 < 10 分钟即刷新」）；
- `PullWxAdDataTask` 直接从表里读最新 token 用，不自己换 token。

表结构见 4.2（`wx_access_token`）。

### 3.1 路线 A（已实测 ✅）：`publisher_adpos_general` 广告汇总数据（自调）

面向"开通流量主的公众号/小程序/小游戏开发者"的数据接口，**用小程序自己的 access_token 直接调用**，不依赖第三方平台。**2026-09-02 已用真实 token 实测返回 `ret:0` 且有数据**。字段口径与后台「流量主 → 数据统计」页面对应。

**只需这一个数据接口**（其余 `publisher_adunit_general` 细分 / `get_adunit_list` 清单 / `publisher_settlement` 结算，本方案不调用，以后要按单元归因或对账再加）：

```
GET https://api.weixin.qq.com/publisher/stat
    ?action=publisher_adpos_general
    &access_token=<TOKEN>
    &page=<N>&page_size=<M>
    &start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
    [&ad_slot=SLOT_ID_WEAPP_xxx]   # 不传=返回全部广告位类型
```

返回：

| 字段 | 说明 | 落库 |
|---|---|---|
| `list[].slot_id` | 广告位类型数字 id（raw） | `slot_id` |
| `list[].ad_slot` | 广告位类型名称 | `ad_slot` |
| `list[].date` | 统计日期 | `stat_date` |
| `list[].req_succ_count` | 拉取量（请求成功数） | `req_succ_count` |
| `list[].exposure_count` | 曝光量 | `exposure_count` |
| `list[].exposure_rate` | 曝光率（0~1） | `exposure_rate` |
| `list[].click_count` | 点击量 | `click_count` |
| `list[].click_rate` | 点击率（0~1） | `click_rate` |
| `list[].income` | 分账收入（**分**） | `income_fen` |
| `list[].ecpm` | 千次曝光收益（**分/千次**） | `ecpm_fen` |
| `summary{}` | 区间合计 | 不单独存（可查库聚合） |
| `total_num` | list 总条数（分页用） | 分页循环依据 |

**广告位类型枚举（ad_slot）及中文名映射（代码内写死，填 `ad_slot_name`）**：

| ad_slot（枚举） | 中文名（ad_slot_name） |
|---|---|
| `SLOT_ID_WEAPP_BANNER` | Banner 广告 |
| `SLOT_ID_WEAPP_REWARD_VIDEO` | 激励视频广告 |
| `SLOT_ID_WEAPP_INTERSTITIAL` | 插屏广告 |
| `SLOT_ID_WEAPP_VIDEO_FEEDS` | 视频广告 |
| `SLOT_ID_WEAPP_VIDEO_BEGIN` | 视频贴片广告 |
| `SLOT_ID_WEAPP_COVER` | **封面广告** |
| `SLOT_ID_WEAPP_BOX` | 格子广告 |
| `SLOT_ID_WEAPP_TEMPLATE` | **原生模板广告**（本小程序当前类型） |

> 未匹配到的枚举兜底：`ad_slot_name` 存 `ad_slot` 原值，避免丢数据。

分页取全：`total_num > page×page_size` 时继续 `page+1`，单次请求跨度 ≤90 天。

### 3.2 路线 B（备选）：`wxa/operationams` 第三方平台代运营接口

若实测路线 A 已下线（报 `45010 无效接口名`）或账号不支持，改用开放平台现行文档的「小程序流量主代运营」接口（[官方文档目录](https://developers.weixin.qq.com/doc/oplatform/openApi/ams/)），对应汇总接口：

```
POST https://api.weixin.qq.com/wxa/operationams?action=agency_get_adpos_genenral&access_token=<authorizer_access_token>
body: { "page":1, "page_size":90, "start_date":"...", "end_date":"...", "ad_slot":"..." }
```

差异：字段 `income` → `publisher_income`（语义/单位不变）；**仅"第三方平台"账号类型代调用**，需开放平台第三方平台 + 小程序授权 + 权限集 + 服务商在"变现专区"开通账户（否则报 `2056`）。账号侧前置成本高，只作备选。见[获取小程序广告汇总数据](https://developers.weixin.qq.com/doc/oplatform/openApi/ams/ad-data/api_getadposgenenral.html)。

### 3.3 错误码与处理策略

| 错误码 | 含义 | 处理 |
|---|---|---|
| 0 / ret=0 | 成功 | 正常入库 |
| 1700 / 1701 | 参数错误 | 检查日期格式/参数，记日志，任务失败 |
| 1735 | 商户未完成协议签署流程 | 提示运营去后台签约；失败并告警 |
| 1737 | 操作过快 | 等 60s 后重试 |
| 45009 | 请求过于频繁 | 指数退避重试（接口间建议 sleep 1~2s） |
| 45010 | 无效的接口名 | 路线 A 已下线 → 切换路线 B |
| 1807 / 2009 | 无效流量主（未开通） | 提示去开通；失败并告警 |
| -202 等 | 微信内部错误 | 短暂重试后放弃，留日志 |

**日期口径**：微信侧 T-1 数据次日才完整、且近期可能有修正 → 每日拉取窗口取 **[T-3, T-1]，滚动 upsert** 覆盖修正，而不是只拉 T-1。

## 四、表设计：两张表

- `wx_ad_daily_stat`：广告数据（核心）
- `wx_access_token`：接口凭证（token 落库，独立任务刷新）

建表脚本按仓库惯例放 `backend-java/scripts/`（一表一文件）。

### 4.1 `wx_ad_daily_stat`（广告数据表）

```sql
-- ============================================================
-- 微信广告日统计表（wx_ad_daily_stat）
-- 用途：每日任务拉取小程序流量主广告汇总数据落库（PullWxAdDataTask），
--       一行 = target(端) × ad_slot(广告位类型) × stat_date(统计日)。
-- 只存广告数据：拉取量 / 曝光 / 点击 / 收入等指标，不存任务日志/字典/结算。
-- 金额单位：income 一律为"分"；ecpm 为"分/千次曝光"。
-- 幂等：以 (target, stat_date, ad_slot) 为业务键 upsert（见唯一索引）。
-- 兼容：PostgreSQL（与后端同库）
-- ============================================================
CREATE TABLE IF NOT EXISTS wx_ad_daily_stat (
    id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    target         VARCHAR(32)  NOT NULL,              -- 端：app.wechat.apps 的 key（shiChang-tracker / ...）
    stat_date      DATE         NOT NULL,              -- 统计日期（微信侧 date 字段）
    slot_id        BIGINT,                             -- 广告位类型数字 id（raw 保留，可空）
    ad_slot        VARCHAR(40)  NOT NULL,              -- 广告位类型枚举：SLOT_ID_WEAPP_TEMPLATE / ...
    ad_slot_name   VARCHAR(32),                        -- 广告位类型中文名：原生模板广告 / banner / ...（代码内枚举映射填值）
    req_succ_count BIGINT       NOT NULL DEFAULT 0,    -- 拉取量（请求成功数）
    exposure_count BIGINT       NOT NULL DEFAULT 0,    -- 曝光量
    exposure_rate  NUMERIC(18,9) NOT NULL DEFAULT 0,   -- 曝光率（0~1）
    click_count    BIGINT       NOT NULL DEFAULT 0,    -- 点击量
    click_rate     NUMERIC(18,9) NOT NULL DEFAULT 0,   -- 点击率（0~1）
    income_fen     BIGINT       NOT NULL DEFAULT 0,    -- 分账收入（分）
    ecpm_fen       NUMERIC(18,9) NOT NULL DEFAULT 0,   -- 千次曝光收益（分/千次）
    pulled_at      TIMESTAMP    NOT NULL DEFAULT now(), -- 本行最近一次被拉取写入的时间
    created_at     TIMESTAMP    NOT NULL DEFAULT now()
);

-- 业务唯一键：同一端同一天同一广告位类型唯一（支持 upsert 幂等）
CREATE UNIQUE INDEX IF NOT EXISTS uk_wx_ad_daily_stat
    ON wx_ad_daily_stat (target, stat_date, ad_slot);

-- 按天看趋势
CREATE INDEX IF NOT EXISTS idx_wx_ad_daily_date
    ON wx_ad_daily_stat (target, stat_date);

COMMENT ON TABLE  wx_ad_daily_stat            IS '微信广告日统计（汇总）：广告位类型 × 天，只存拉取/曝光/点击/收入指标';
COMMENT ON COLUMN wx_ad_daily_stat.ad_slot      IS '广告位类型枚举（SLOT_ID_WEAPP_TEMPLATE / ...）';
COMMENT ON COLUMN wx_ad_daily_stat.ad_slot_name IS '广告位类型中文名（原生模板广告 / banner / ...），代码内枚举映射填值，微信侧不返回';
COMMENT ON COLUMN wx_ad_daily_stat.income_fen IS '分账收入，单位：分';
COMMENT ON COLUMN wx_ad_daily_stat.ecpm_fen   IS '广告千次曝光收益，单位：分/千次曝光';
```

> upsert 语句形态（dao 内实现时参考）：
> `INSERT INTO wx_ad_daily_stat (target, stat_date, slot_id, ad_slot, req_succ_count, exposure_count, exposure_rate, click_count, click_rate, income_fen, ecpm_fen) VALUES (...) ON CONFLICT (target, stat_date, ad_slot) DO UPDATE SET req_succ_count=EXCLUDED.req_succ_count, ..., pulled_at=now();`

### 4.2 `wx_access_token`（接口凭证表）

```sql
-- ============================================================
-- 微信接口凭证表（wx_access_token）
-- 用途：存储各端小程序的 access_token，由 RefreshWxAccessTokenTask 定时刷新，
--       PullWxAdDataTask 直接从本表取最新 token 调用 publisher/stat，不自行换取。
--   - 每端（source）一行；secret 不落库，仍从 app.wechat.apps.<source>.appSecret 读。
--   - 微信 token 有效期 7200s；RefreshWxAccessTokenTask 每 20 分钟刷新一次，始终早于过期。
-- 兼容：PostgreSQL（与后端同库）
-- ============================================================
CREATE TABLE IF NOT EXISTS wx_access_token (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    target      VARCHAR(32)  NOT NULL,              -- 端：app.wechat.apps 的 key（shiChang-tracker / ...）
    access_token VARCHAR(512) NOT NULL,             -- 微信 access_token
    expires_at  TIMESTAMP    NOT NULL,              -- token 过期时间（换得时间 + expires_in）
    refreshed_at TIMESTAMP   NOT NULL DEFAULT now(), -- 最近一次刷新时间
    created_at  TIMESTAMP    NOT NULL DEFAULT now()
);

-- 每端一行
CREATE UNIQUE INDEX IF NOT EXISTS uk_wx_access_token
    ON wx_access_token (target);

COMMENT ON TABLE  wx_access_token             IS '微信接口凭证：每端一条，独立任务定时刷新';
COMMENT ON COLUMN wx_access_token.expires_at  IS '过期时间；刷新任务据此判断是否提前续期';
```

> 刷新任务的 upsert 形态：`INSERT ... ON CONFLICT (target) DO UPDATE SET access_token=EXCLUDED.access_token, expires_at=EXCLUDED.expires_at, refreshed_at=now();`

## 五、存储与调度设计

1. **token 刷新任务 `RefreshWxAccessTokenTask`**：独立定时任务，**每 20 分钟刷新一次**（`@Scheduled(cron = "0 */20 * * * *")`），遍历 `app.wechat.apps` 各端，调 `cgi-bin/token` 换新 token 并 upsert 到 `wx_access_token`（`ON CONFLICT (target)`），每端独立 try/catch。token 有效期 7200s（2h），每 20 分钟刷一次远早于过期，保证任何时刻表里都是新鲜 token。
2. **广告拉取任务 `PullWxAdDataTask`**：`@Scheduled(cron = "0 5 9 * * *")`（北京时间 09:05，T-1 数据已完整），执行开关放 `AppProperties`（如 `app.wechat.ad.pull-enabled`），风格对齐 `YahooDailyFetchScheduler`。每端循环：
   1. 从 `wx_access_token` 读最新 token（拿不到则跳过并告警）；
   2. `publisher_adpos_general` 拉 **[T-3, T-1]**，`page_size=90` 分页取全；
   3. 逐行 upsert 进 `wx_ad_daily_stat`（`ad_slot_name` 由枚举映射填）；
   4. 失败只记 logback 日志 + 告警（不建日志表），幂等靠唯一键 upsert，下次跑自动补齐/覆盖。
3. **补数**：滚动窗口 upsert = 微信侧数据修正后重拉即覆盖；漏跑某日时改窗口手动触发即可，无需清表。
4. **保留**：每天每广告位类型一行，量级极小，无归档压力。
5. **代码分层（后续实施文件清单）**：
   - `backend-java/scripts/wx_ad_daily_stat.sql`、`backend-java/scripts/wx_access_token.sql`
   - `model/WxAdDailyStat.java`、`model/WxAccessToken.java`
   - `dao/WxAdDataRepository.java`（JdbcTemplate + 批量 upsert；对齐 `NoticeRepository`）、`dao/WxAccessTokenRepository.java`
   - `service/WxAdService.java`（token 换/存/取、汇总接口调用、错误码翻译；复用 `WechatService` 的 `app.wechat.apps` 配置与 api.weixin.qq.com baseUrl 风格）
   - `config/AppProperties.Wechat` 增加 ad 拉取开关与默认窗口天数
   - `task/RefreshWxAccessTokenTask.java`（定时刷 token）、`task/PullWxAdDataTask.java`（每日拉广告数据）
