# 埋点打点方案

> 本文档面向前端（`front/`）埋点实现者与后端接口对接，定义统一的打点约定。
> 后端接口已实现（`POST /api/v1/track/events` + `click_event` 表），见 `docs/API.md`「七、用户行为打点」。

## 一、目标

记录「用户用了什么功能」，用于产品分析、漏斗、留存。前后端各司其职：

- **前端**：埋点采集（进页面、点击、搜索、切主题、分享等）+ 攒批上报。
- **后端**：接收、幂等去重、落 `click_event` 表（已实现，本轮不改前端即可用）。

## 二、事件命名规范

统一点分命名 `模块.对象.动作`，用前缀即可聚合。三类事件：

| event_name | eventType | 说明 |
|---|---|---|
| `page.view` | page_view | 进入页面（自动，全页面统一） |
| `page.hide` | page_hide | 离开页面（自动，带 durationMs） |
| `tab.switch` | action | 切换底部 Tab |
| `search.submit` | action | 提交搜索，props 带 keyword |
| `search.result_tap` | tap | 点搜索结果，target=股票 code |
| `stock.detail.view` | page_view | 个股详情 |
| `sector.detail.view` | page_view | 板块详情 |
| `minute.view` | page_view | 分时图，target=code |
| `news.list.view` | page_view | 新闻列表 |
| `news.detail.view` | page_view | 新闻详情 |
| `share.trigger` | action | 触发分享，props 带来源页 |
| `theme.switch` | action | 切主题，props 带 light/dark |
| `feedback.submit` | action | 提交反馈 |
| `login.action` | action | 登录成功 |

> 命名增删以本表为准；新增事件直接 `track('新.名')`，无需改后端（`event_name` 是自由字符串）。

## 三、上报接口契约

```
POST /api/v1/track/events
Authorization: Bearer {token}   // 登录后必带（后端据此解析 user_id）；登录前可不带（匿名上报）
```

请求体（批量，单批 ≤ 100）：

```json
{
  "events": [
    {
      "eventId": "1724000000000-abc123-1",
      "eventName": "search.submit",
      "eventType": "action",
      "page": "pages/search/index",
      "target": "",
      "props": { "keyword": "茅台" },
      "durationMs": null,
      "sessionId": "1724000000000-abc123",
      "clientTs": 1724000000123,
      "platform": "ios",
      "appVersion": "1.2.3"
    }
  ]
}
```

响应：

```json
{ "code": 200, "msg": "success", "data": { "accepted": 1, "duplicated": 0, "invalid": 0 } }
```

## 四、前端实现要点（SDK 骨架）

新建 `front/utils/tracker.ts`，核心：**内存队列 + 攒批 + 幂等 eventId + 三时机 flush**。

```ts
let queue: TrackEvent[] = []
let seq = 0
const sessionId = `${Date.now()}-${Math.random().toString(36).slice(2)}`

export function track(eventName: string, extra?: Partial<TrackEvent>): void {
  queue.push({
    eventId: `${sessionId}-${++seq}`,
    eventName,
    eventType: extra?.eventType,
    page: currentPage(),
    target: extra?.target,
    props: extra?.props,
    durationMs: extra?.durationMs,
    sessionId,
    clientTs: Date.now(),
    platform: platformInfo(),
    appVersion: getAppVersion(),
    ...extra,
  })
  if (queue.length >= 50) void flush()
}

export function flush(): Promise<void> {
  if (!queue.length) return Promise.resolve()
  const events = queue.splice(0, queue.length)
  return request({ path: '/api/v1/track/events', method: 'POST', data: { events }, withAuth: true })
    .catch(() => { queue.unshift(...events) }) // 失败放回重试（event_id 幂等兜底）
}
```

**flush 触发时机（三处）：**

1. 定时器：每 10s 或队列 ≥ 50 条；
2. `App.onHide` / `wx.onAppHide` / `App.onError`；
3. 关键页 `onUnload`（可选保险）。

**自动 PV 用 `wx.onAppRoute`（全局一处，免改 14 个页面）：**

```ts
// app.ts 里注册
wx.onAppRoute((res) => {
  endPageStay()                          // 给上一个页面补 page.hide + durationMs
  startPageStay(res.path)                // 记录新页面进入时间
  track('page.view', { page: res.path, eventType: 'page_view' })
})
```

- `wx.onAppRoute` 覆盖 `navigateTo / switchTab / reLaunch / redirectTo` 全路由。
- 关键动作（搜索、点个股、切主题、分享）在对应回调里**一行** `track(...)`。

## 五、合规与性能注意

1. **绝不上报** openid / 手机号 / 昵称，只报 `user_id`（后端解析）。
2. `props` 里的业务参数（keyword 等）超长截断（如 keyword 32 字）。
3. 上报走独立异步 `wx.request`，不阻塞业务；后端批量插入。
4. 行情页 8s 自动轮询**不埋点**，只有用户主动动作才 `track`，天然低频。
5. 事件丢失可接受：定时 flush(10s) + onHide flush，最多丢最近几秒。
