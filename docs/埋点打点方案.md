# 埋点打点方案

> 本文档面向前端（`front/`）埋点实现者与后端接口对接，定义统一的打点约定。
> 后端接口已实现（`POST /api/v1/track/events` + `click_event` 表），见 `docs/API.md`「七、用户行为打点」。
> **前端 SDK 已落地**（`front/utils/tracker.ts`，2026-08-25），本文档「四」为实际实现的说明。

## 一、目标

记录「用户用了什么功能」，用于产品分析、漏斗、留存。前后端各司其职：

- **前端**：埋点采集（进页面、点击、搜索、切主题、分享等）+ 攒批上报。
- **后端**：接收、幂等去重、落 `click_event` 表（已实现）。

## 二、事件命名规范

统一点分命名 `模块.对象.动作`，用前缀即可聚合。三类事件：

| event_name           | eventType | 说明                                 | 调用（trackEvent key 与参数）                                    |
| -------------------- | --------- | ------------------------------------ | ---------------------------------------------------------------- |
| `page.view`          | page_view | 进入页面（自动，全页面统一）         | 自动（wx.onAppRoute 采集，页面无感）                             |
| `page.hide`          | page_hide | 离开页面（自动，带 durationMs）      | 自动（路由切换 / App 退后台时补发）                              |
| `tab.switch`         | action    | 切换底部 Tab                         | `trackEvent('tab.switch', tabKey)`                               |
| `search.submit`      | action    | 提交搜索，props 带 keyword           | `trackEvent('search.submit', keyword)`（空白不埋，截断 32 字）   |
| `search.result_tap`  | tap       | 点搜索结果，target=股票 code         | `trackEvent('search.result_tap', code)`                          |
| `news.detail.view`   | page_view | 查看新闻详情，props 带 id + 标题     | `trackEvent('news.view', { id, title })`                         |
| `market.card_tap`    | tap       | 点行情卡片查看分时，target=卡片 code | `trackEvent('card.tap', { code, name, minuteCode })`             |
| `info.tip_open`      | tap       | 点「i」图标打开说明弹窗              | `trackEvent('tip.open', sectionTitle)`（空白不埋）               |
| `share.trigger`      | action    | 触发分享，props 带来源页；新闻详情页另带新闻 id + 标题 | `trackEvent('share.trigger')`（零参数）；新闻页 `trackEvent('share.trigger', { id, title })` |
| `theme.switch`       | action    | 切主题，props 带 system/light/dark   | `trackEvent('theme.switch', pref)`                               |
| `login.action`       | action    | 登录成功                             | `trackEvent('login.action')`（零参数）                           |
| `stock.detail.view`  | page_view | 个股详情                             | 由 `page.view` 覆盖（target=query.code），不单独上报             |
| `sector.detail.view` | page_view | 板块详情                             | 由 `page.view` 覆盖（target=query.code）                         |
| `minute.view`        | page_view | 分时图，target=code                  | 由 `page.view` 覆盖（target=query.code）                         |
| `news.list.view`     | page_view | 新闻列表                             | 由 `page.view` 覆盖（个股新闻列表 target=query.code）            |
| `feedback.submit`    | action    | 提交反馈                             | ⏸ 未落地：反馈页（pages/custom）无提交表单，仅展示联系方式二维码 |

> 命名增删以本表为准；**新增事件 = `TRACK_EVENT_DEFS` 加一行 + 调用处一行 `trackEvent(key, params)`**
> （`event_name` 是自由字符串，无需改后端）。
> 带调用方式的事件已埋；标记「由 page.view 覆盖」的事件统一走 `page.view` + target，避免同一访问双计。

## 三、上报接口契约

```
POST /api/v1/track/events
Authorization: Bearer {token}   // 必带：前端只在登录成功后才上报（后端据此解析 user_id）
```

请求体（批量，单批 ≤ 100）：

```json
{
  "events": [
    {
      "eventId": "1724000000000-abc123-1",
      "eventName": "search.submit",
      "eventType": "action",
      "page": "pages/search/index",
      "target": "",
      "props": { "keyword": "茅台" },
      "durationMs": null,
      "sessionId": "1724000000000-abc123",
      "clientTs": 1724000000123,
      "platform": "ios",
      "appVersion": "1.2.3"
    }
  ]
}
```

响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": { "accepted": 1, "duplicated": 0, "invalid": 0 }
}
```

## 四、前端实现要点（已落地）

**统一入口：`trackEvent(key, params)`**（`front/utils/tracker.ts`）。

事件定义集中声明在 `front/config/tracking.ts` 的 **`TRACK_EVENT_DEFS`**（事件名 / eventType /
固定 page / target 取值 / props 字段映射），调用方只传业务参数，新增事件 = 定义表加一行 +
调用处一行 `trackEvent`，**无需再写辅助函数**。运行配置在 `front/config/tracking.ts`，
类型与定义表类型在 `front/types/tracking.ts`。

```ts
// 页面 / 组件里直接调用，尽量少传参：
trackEvent("tab.switch", "finance"); // 标量 → target（有 target 定义时）
trackEvent("search.submit", "茅台"); // 标量 → 唯一 props 字段（keyword）
trackEvent("search.result_tap", "600519"); // 标量 → target（股票 code）
trackEvent("news.view", { id, title }); // 对象 → 按定义表映射 props
trackEvent("card.tap", { code, name, minuteCode });
trackEvent("tip.open", "金银"); // 标量 → 唯一 props 字段（section）
trackEvent("share.trigger"); // 零参数（props.source 自动取当前页）；新闻详情页传 { id, title } 记录被分享的新闻
trackEvent("theme.switch", "dark");
trackEvent("login.action"); // 零参数
```

**params 规则（尽量少传）：**

- 标量（string / number / boolean）：定义表声明了 `target` 时直接作 target；否则作唯一 props 字段的值；
- 对象：按定义表 `target` / `props` 声明的字段名取值；
- 不传：用于无需业务参数的事件（`share.trigger` / `login.action`）；
- `required` 字段缺失 / 空白时不产生事件（如搜索关键词）；未登记的事件不产生数据（console.warn 提示）。

**自动 PV 用 `wx.onAppRoute`（全局一处，免改 14 个页面）：**

```ts
// app.ts onLaunch 里 initTracker() 注册一次
wx.onAppRoute((res) => {
  endPageStay(); // 给上一个页面补 page.hide + durationMs
  startPageStay(res.path, res.query); // 记录新页面进入时间；详情页从 query 取 code 作 target
  track("page.view", {
    page: res.path,
    eventType: "page_view",
    target: res.query?.code,
  });
});
```

- `wx.onAppRoute` 覆盖 `navigateTo / switchTab / reLaunch / redirectTo` 全路由（基础库 2.4.4+，
  低版本无此接口时自动退化为 `App.onShow` 冷启动兜底，只少自动 hide）。
- 冷启动首帧若路由事件晚于 `App.onShow`，由 `App.onShow` 兜底补发首个 `page.view`；
  后台返回时由 `App.onShow` 重新开始停留并补发 `page.view`（每次进入前台 = 一次新访问，view/hide 成对）。
- **登录门闩（打点只在登录成功后才上报）**：app.ts 里
  `setTrackingLoginWaiter(() => rootStore.auth.ensureLogin())`，`flush()` 发请求前先 await 该
  Promise —— 返回 true（登录成功）才真正上报（`request` 带 `Bearer`，后端解析 `user_id`）；
  返回 false（登录失败 / 未完成）时事件留在队列，等定时器 / onHide / 下一次 flush 再试，
  **绝不匿名上报**。登录前的 page.view 等事件先入队，登录成功后随下一批补报。
- 关键动作（搜索、点结果、切 Tab、切主题、分享、登录、看新闻、点卡片进分时、开说明弹窗）
  在各回调里**一行** `trackEvent(...)`；`props` 是自由 JSON 扩展参数，按事件语义携带业务字段
  （如新闻 id/标题、卡片名称/取数代码、分区标题），组装规则统一在定义表声明。

**flush 触发时机（三处）：**

1. 定时器：每 10s（`startFlushTimer`）或队列 ≥ 50 条（`track` 内触发）；
2. `App.onHide`（结算页面停留后立即 flush）、`App.onError`；
3. 上报失败自动放回队首重试，队列超上限（200）丢最旧，`eventId` 幂等兜底不重复计数；
   登录未成功时不发请求，事件保留（登录成功后自动补报）。

## 五、合规与性能注意

1. **打点只在登录成功后上报**，`user_id` 恒有；**绝不上报** openid / 手机号 / 昵称。
2. `props` 里的业务参数（keyword 等）超长截断（keyword 32 字、其余字符串 256 字），
   并剔除 `undefined` / 函数字段，防脏数据撑大请求体。
3. 上报走独立异步 `wx.request`，不阻塞业务；后端批量插入。
4. 行情页 8s 自动轮询**不埋点**，只有用户主动动作才 `track`，天然低频。
5. 事件丢失可接受：定时 flush(10s) + onHide flush，最多丢最近几秒；失败重试队列上限 200 防堆积。
6. **region 字段暂不上报**：后端 `click_event` 尚未实现 `region` 列（见
   `docs/superpowers/specs/2026-08-24-track-region-design.md` 计划），前端等后端支持后再加。
