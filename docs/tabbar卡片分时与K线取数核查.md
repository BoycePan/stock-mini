## 二、核查范围与卡片清单

### 2.1 清单来源

卡片清单不是手写的，而是从**生产配置**推导（脚本放在仓库外的一次性命令中，未新增仓库文件）：

- `front/config/tabbar.ts`：`GLOBAL_INDICES` / `AVG_PRICE_CONFIG` / `MACRO_ASSETS` / `INDUSTRY_BOARDS` /
  `ASIA_INDICES` / `ASIA_KR_STOCKS` / `ASIA_JP_STOCKS` / `ASIA_RATES` / `METALS` / `METAL_SECTIONS`；
- `front/config/gold-shop.ts`、`front/config/physical-gold.ts`（金店金价、实物黄金，非行情卡）；
- `front/api/market.ts` 的**会话变体规则**：美股 Tab 板块 `us-BKxxxx`、美股盘前 `us-pre-BKxxxx`、
  金银内外盘双卡、工业/其他金属的 `*-US` / `us-*` 变体；
- 源判定用生产函数 `resolveMinutePlan` / `resolveKlineSources` / `hasMinuteSources` / `hasKlineSources`。

## 四、缺口清单（含根因、证据与可用替代源）

本节的 5 项中，**§4.1 / §4.2 / §4.4 是稳定复现的真实缺陷**（3 个板块全空 + 1 个板块错值 + 1 个板块年K 空），

### 4.1 三个美股板块 K 线四 TAB 全空 —— 交易所后缀映射缺陷（**本次核查最重要的发现**）

| 卡片 | 现象 | 实测证据 |
| --- | --- | --- |
| 全球页 · 行业板块（美股Tab）· **CPO** `us-BK1128` | 日/周/月/年 **全空**（分时正常：391 点） | 5 条代理腿中 `106.COHR`、`106.CIEN` 命中的是坏序列 |
| 全球页 · 行业板块（美股Tab）· **证券** `us-BK0473` | 全空 | `106.SCHW` 命中坏序列 |
| 全球页 · 行业板块（美股Tab）· **消费电子** `us-BK1037` | 全空 | `106.DELL` 命中坏序列 |

根因（可复现，两步）：

1. `front/config/kline.ts` 对美股 secid 生成的腾讯代码候选顺序是固定的
   `us<TICKER>.OQ → us<TICKER>.N → us<TICKER>.A`（与东财市场号 105=纳斯达克 / 106=纽交所 / 107=美交所 **不对应**）；
2. 腾讯 `usfqkline` 对**错误后缀**有第二种坏返回：不是「只回 1 根」（会被 `MIN_KLINE_BARS=2` 拦掉、正确落到下一候选），
   而是**回 500 根「最早历史 + 最新一根」**——根数 ≥2，于是被判为有效并**固定使用**该后缀：

   | 代码 | `.OQ`（错误后缀，被采用） | `.N`（正确后缀） |
   | --- | --- | --- |
   | `usCOHR.OQ` | 500 根 `2021-03-02→2026-09-17`（近一年 **1** 根） | `usCOHR.N` 500 根 `2024-09-19→2026-09-17`（近一年 251 根） |
   | `usCIEN.OQ` | 501 根 `2011-12-30→2026-09-17`（近一年 **1** 根） | `usCIEN.N` 500 根（近一年 251 根） |
   | `usSCHW.OQ` | 501 根 `2010-12-27→2026-09-17`（近一年 **1** 根） | `usSCHW.N` 500 根（近一年 251 根） |
   | `usDELL.OQ` | 501 根 `2011-11-01→2026-09-17`（近一年 **1** 根） | `usDELL.N` 500 根（近一年 251 根） |

3. 板块 K 线是**代理腿日线均值合成**，而合成要求「所有腿都有该交易日」（`fetchProxyComposite` 的公共交易日交集）。
   某条腿只有「2011–2014 + 最新一根」时，交集塌缩为 **1 天** → `normalizeKlines` 返回 null → **整块板四个 TAB 全空**。

30 个美股板块的全量审计结果：**3 块板交集塌缩为 1 天（空）**，**1 块板交集 500 天但跨度 10 年（错值）**，其余 26 块正常（交集 500 天、`2024-09-19→2026-09-17`）。

### 4.2 一个美股板块取到「稀疏错值」—— 机器人 `us-BK1090`

- 生产链路实测：`us-BK1090` 日K = **500 根 `2016-05-11→2026-09-17`，近一年仅 1 根**（来源：代理股日线均值合成）。
- 即：图上有数据，但实际是「2016 年起的老序列 + 最新一根」拼出来的**错图**（跨度 10 年、每 2 周才 1 根），并非「空态」，因此不会被空态提示暴露。
- 根因同上：唯一代理腿 `107.ROBO` 命中 `usROBO.OQ` 坏序列（500 根 `2016-05-11→2026-09-17`，近一年 1 根）；
  `usROBO.N` / `usROBO.A` 均无数据（0 根）。
- **可用源已找到**：新浪美股 `ROBO` 实测 **2104 根 `2018-05-04→2026-09-17`（近一年密集）**。

### 4.3 费城半导体指数 `SOX` 年K **偶发为空** —— 年K 依赖新浪兜底聚合

- 东财 `251.SOX` 只回 **53 根日线（2026-07-06 起）/ 11 根周线 / 3 根月线**（该 secid 是东财新上的口径，历史很短），
  日/周 TAB 正常但月K 只有 3 根，**年K 无法由它聚合出 ≥2 根**。
- 年K 因此必须依赖新浪兜底（`SOX` 配置里已有 `sina: { kind: 'us', symbol: '.SOX' }`）：实测新浪 `.SOX`
  **3185 根 `2014-01-16→2026-09-17`**，聚合后 **13 根年K**（周K 662 根、月K 153 根）。

- **K线链路（东财 `push2his`）在连续请求下会进入限流**：故障表现是 **98–300ms 的快速失败**（连接被重置，非超时），
  同一时刻不同 secid 时好时坏。限流窗口内的成功率实测（主/备节点交替，各 8 次）：

  | 请求 | 成功率 | 说明 |
  | --- | --- | --- |
  | `100.SENSEX` 日K（限流窗口 A） | 0/8 | 而同一标的的周K/月K/年K 均有数据 |
  | `100.KS11` 日K（对照） | 3/8 | 同一 secid 时好时坏，证明是节点限流而非标的无数据 |
  | `100.SENSEX` 月K | 1/8 | 同上 |
  | `100.SENSEX` 日K（限流窗口 B，10 分钟后复测） | 5/8 | 同一标的已能稳定取到 500 根 → 证明确为限流而非缺口 |

- 备用节点 `82.push2his.eastmoney.com` 能**部分绕过**：实测同一 secid 主节点失败、备用节点返回 200/500 根；
  生产代码已在 `api/kline.ts` 里做「主节点 → 备用节点」轮换。
- 影响面：**K线为东财单源的标的**（30 个 A股板块、A股平均股价 `AVG`、`KS11`、`VNINDEX`、`SENSEX`、日韩 16 只个股、`SOX`）
  在限流窗口内会整体落到「该周期暂时无法获取数据，请稍后重试」空态；分时不受影响。
- 结论：这是**稳定性风险**而非功能缺陷。判定依据：两轮采集中出现的零星空 TAB 随后都能取到
  （`SENSEX` 日K 在窗口 B 5/8 成功并最终取到 500 根；`SOX` 年K 6 次中 4 次成功；首轮的 8 个失败 code 复验全部恢复）。
