# 行情页多周期图表（分时 / 五日 / 日K / 周K / 月K / 年K + 成交量 + MACD）

> 需求：`packageQuote/pages/minute/index` 的分时图增加周期 TAB（分时 / 五日 / 日K / 周K / 月K / 年K），
> 成交量下方增加 MACD，**只用国内接口**，覆盖全部标的（没有该周期数据源时 TAB 置灰提示），
> 布局与配色在浅色 / 深色两套主题下都要清晰、不拥挤。
>
> 落地：TAB 切换复用同一张画布（`packageQuote/components/quote-chart`），
> 分时走东财 `trends2`（`ndays=1`），五日走腾讯 `dayus` / `day` 多日分钟线（东财 `ndays=5` 已实测失效，见下），
> 日/周/月 K 走腾讯 K 线（新浪兜底），年 K 由月 K 聚合（国内无年 K 直连源）。

## 一、数据源（全部国内直连，实测证据见第四节）

| 周期 | 首选源 | 兜底链 | 说明 |
| --- | --- | --- | --- |
| 分时 | 东财 `push2delay/api/qt/stock/trends2/get?ndays=1` | 腾讯 `minute/query` → Yahoo 1分钟 | 既有链路不变（见 `docs/minute-api.md`） |
| 五日 | 腾讯 `appstock/app/dayus/query`（美股）/ `appstock/app/day/query`（A股 / 港股 / A股指数） | 新浪 A股 5 分钟 K 线 → 东财 `push2/api/qt/stock/trends2/get?ndays=5`（**校验跨日**） | 东财 push2 与 push2delay 都**静默忽略 ndays**（只回当日），故五日改由腾讯承担主链，见下 |
| 日 K | 腾讯 `web.ifzq.gtimg.cn/appstock/app/{fqkline,usfqkline,kline}/get` | 新浪 A股 / 美股日 K | 覆盖率最高（A股 / 港股 / 日股 / 韩股 / 美股个股 / 美股指数 / 外汇） |
| 周 K | 腾讯 `week` | 新浪 A股 `scale=1680` → 日 K 聚合 | 腾讯周线对韩股等市场只返回 1 根 → 自动回退日 K 聚合 |
| 月 K | 腾讯 `month` | 周 K 聚合 → 日 K 聚合 | 同上 |
| 年 K | **无直连源** | 月 K 聚合 → 周 K 聚合 → 日 K 聚合 | 风控原因见下 |

### 五日的坑：东财 `ndays=5` 在两个 push2 节点都是空参数（实测）

**2026-09-15 复测结论（浏览器直连 + 小程序抓包交叉验证）**：

| 端点 | `ndays=5` 实测 | 结论 |
| --- | --- | --- |
| `push2delay.eastmoney.com/api/qt/stock/trends2/get` | `1.000001` 回 241 行（当日）；`100.DJIA` / `105.NVDA` 回当日 391 行 | **忽略 ndays** |
| `push2.eastmoney.com/api/qt/stock/trends2/get` | 同上（`ndays=1` 与 `ndays=5` 返回逐字节同长度） | **忽略 ndays** |
| `push2his.eastmoney.com/api/qt/stock/trends2/get` | `1.000001` 回 1205 行 / 5 个自然日；`100.DJIA` 回 1596 行 / 6 个北京日期（美股时段跨零点） | 支持 ndays=5，但小程序环境被风控重置（东财自家小程序抓包同样 504 / 0 字节），**不可依赖** |
| 腾讯 `web.ifzq.gtimg.cn/appstock/app/dayus/query` | `usDJI` / `usINX` / `usIXIC` / `usNVDA` / `usTLT` 回 **5 个交易日 × 1 分钟**（391 行 / 日，09:30-16:00 ET） | **美股五日主源** |
| 腾讯 `web.ifzq.gtimg.cn/appstock/app/day/query` | `sh600519` / `hk00700` / `sh000001` 回 5 个交易日 × 1 分钟 | A股 / 港股 / A股指数主源 |

因此五日不再是「东财优先 + 腾讯兜底」，而是按「腾讯主链 + 东财兜底」组织，且每个源都校验
「是否真的跨 ≥2 个自然日」（`countPointDays`）：

1. **腾讯 `dayus/query`（美股）**：美股指数（usDJI / usINX / usIXIC）与美股个股 / ETF
   （`105.NVDA` → `usNVDA`、`106.BRK_B` → `usBRK.B`）→ 5 个交易日 × 1 分钟；
   行内只有 3 列 `HHmm 现价 累计成交量`（无累计额）→ 单分钟量按累计差分、均价恒空；
2. **腾讯 `day/query`（A股 / 港股 / A股指数）**：实测最近 5 个交易日 × 1 分钟；
3. **新浪 A股 5 分钟 K 线**（`scale=5&datalen=240` ≈ 5 个交易日）；
4. **东财 push2 `ndays=5`**：兜底板块 / 期货 / 外汇 / 日韩指数等无腾讯五日源的标的；
   由于上游忽略 ndays，通常会被跨日校验拦下（此时页面展示「该周期暂无数据」，其余周期不受影响）。
   保留该请求是为了东财放开多日后能自动生效——排在最后而不是最前，避免 A股 / 港股 / 美股
   每次打开五日都白等一次往返（该节点还常被反爬重置，最坏要等到超时）。

> 五日口径：以**区间首点价格**为 0% 基准（美股与 A股源的昨收口径不同，统一按首点对齐，
> 曲线从 0% 起步）；腾讯行内第 3/4 列是**累计**量 / 额（A股 / 港股），做差分得到单分钟量，
> 均价按 `累计额 ÷ (累计手数 × 100)` 推算并用「是否落在现价 0.5~2 倍」做合理性校验
> （指数无「每股价格」概念 → 该标的不出均价线；美股行无累计额 → 均价同样为空）；
> A股 数据里收盘后 15:01-15:30 的固定价行用既有交易时段模型过滤掉，避免五日线多出一段平尾。
> 美股源的时间口径是**交易所本地时钟**（09:30-16:00 ET，5 个自然日分段），
> 与东财美股分时的北京时间口径（21:30-04:00，跨两个北京日期）不同，但五日按日分段绘制，两者曲线一致。

### 为什么不用东财 K 线

东财历史 K 线只有 `push2his.eastmoney.com` / `82.push2his.eastmoney.com` 节点提供；
延迟节点 `push2delay` 明确返回空数据（实测 `{"data":{"code":"600519","klines":[]}}`），
而 `push2his` 在小程序客户端被反爬拦截（实测连接重置，见 `docs/魔方板块分析/魔方板块-接口文档.md`）。
因此 K 线改用**腾讯 + 新浪**两个国内源，年 K 用聚合补齐。

### 为什么不用腾讯 app 侧 K 线（`proxy.finance.qq.com`）

`docs/数据源备用接口参考文档.txt`（抓包）里有 `proxy.finance.qq.com/cgi/cgi-bin/stockinfoquery/kline/app/get`
（`ktype=day|week|month|**year**`，`nodes[]` 结构，**原生支持年 K**），但该接口带
`fskey` / `appid` / `openid` / `check` 等签名参数：实测**不带签名与照搬抓包签名均无响应**
（返回空 body，疑似按小程序 appid + 会话签名校验），不可作为稳定依赖，故未纳入。

## 三、图表设计（三块面板，有则展示）

```
┌──────────────────────────────────────────────┐
│ MA5  MA20  MA30  MA60（K线）← 图例行（自适应） │
│ 价格主图：网格 + 左侧刻度（分时/五日中线为 0%） │
│   分时/五日：分段着色价格线 + 均价线（黄）       │
│   K 线：蜡烛 + MA5/20/30/60 + 最新价虚线标签    │
├──────────────────────────────────────────────┤
│ 成交量：柱按涨跌分色（K线实色、分时半透明）      │
├──────────────────────────────────────────────┤
│ MACD(12,26,9)：零轴居中 + 红绿柱 + DIF/DEA 双线 │
└──────────────────────────────────────────────┘
   [ 30 / 320 根 ]                    [+][−][‹][›]
   ↑ K 线模式下的窗口文案与缩放 / 平移控件
```

- **顺序与可见性**：价格 → 成交量 → MACD；成交量全为 0（外汇等）时整块隐藏，
  K 线不足 34 根（`slow + signal - 1`）时隐藏 MACD 面板，**隐藏后空闲高度自动给价格主图**，
  不会留下空白条；分时 / 五日不出 MACD（同一张图内没有 K 线序列，MACD 无意义）；
- **K 线可见窗口（默认 30 根）**：日/周/月/年 K 不再一次画几百根（又卡又糊），
  默认只画**最近 30 根**（板块 / 个股详情页的 `kline-chart` 同步如此），改窗口只有按钮 + 双指：
  1. **`‹` / `›`：轻点移动 1 根**，长按约 400ms 起连发（每 80ms 一次，步长每 10 次加 1 根：
     1 → 2 → 3 …），长历史几秒翻到头；贴到首 / 尾后按钮置灰，左侧显示「当前根数 / 全量根数」；
  2. `+` / `−` 缩放：根数 ×0.7 / ÷0.7（右端锚定，窗口停在最新一根时始终贴着最新）；
  3. **双指捏合**缩放：指距放大 = 根数变少，锚点定住两指中点那一根（手感与系统缩放一致），
     指距变化 <2% 的死区忽略，避免手指抖动把窗口来回抖。
  **单指只用于查看数据**：按下 / 滑动都只把十字光标移到手指位置（读数不断线），
  **不会拖动 K 线**——避免「想看一下数值却把图拖走」；分时 / 五日没有窗口，行为同样只有十字光标。
  **上下限**（`utils/kline-viewport.ts`）：根数 ∈ [10 根, 全量]，`viewEnd` ∈ [0, 总数-1]，
  任何路径都经 `clampViewport` 夹回 —— 既不会放大到一根都看不见，也不会缩到窗口比数据还长、
  更不会挪出数据范围。切 TAB / 重新取数时窗口复位到最新 30 根（主题切换保留你调好的窗口）。
  **均线与 MACD 一律在全量 K 线上算完再按窗口切片**（`buildKlineView`）：
  若只在 30 根窗口内计算，MA60 会因为预热不足直接画不出来；
- **均线周期**：`utils/kline.ts` 的 `KLINE_MA_PERIODS = [5, 20, 30, 60]` 是单一数据源，
  屏幕 K 线图（行情页与板块 / 个股详情页）与分享海报（`utils/kline-poster.ts`）共用；
  图例带数值并自适应——放不下先降字号（10px → 9px），再放不下只留周期名
  （`utils/kline-legend.ts`），避免四条均线的数值互相叠压；
- **纵轴范围**：K 线的价格上下界把可见窗口内的均线一并算进去
  （`computeKlineRange(klines, 0.06, maSeries)`）——窗口只有 30 根时 MA60 会落在
  K 线高低点之外（强趋势段），不并入就会被画到价格面板外、压住成交量面板；
  实测 `usDJI` / `sh600519` / `NVDA` 日 K 的 30 根窗口都会出现这种情况；
  另外全为正价时下界夹到 0，避免长期前复权序列（年 K 由月 K 聚合，跨度数百倍）
  出现「-135.80」这类不存在的价格刻度；
- **五日 / 分时的均价线（黄）**：A股 / 港股按真实累计成交额推算（额 ÷ 量，手 / 股两种量纲自动识别）；
  指数（无量价换算关系）与美股 dayus（行内无累计额）退化为**成交量加权近似**，
  即当日成交重心，页面口径提示中已注明为近似值；完全无量的标的不出均价线；
- **十字光标**：竖线贯穿三块面板，横线在价格面板，信息框按模式给出不同字段
  （分时：时间/价格/涨跌/均价/量；K 线：时间/开/高/低/收/涨跌/量），
  成交量与 MACD 顶行数值随选中的那根实时切换（同花顺式）；
- **配色**：涨 `#eb514d` / 跌 `#20a66a` 两主题一致；网格、文字、零轴、信息框底色随主题切换
  （浅色网格 `rgba(20,32,51,0.08)` + 文字 `#718096`；深色网格 `rgba(255,255,255,0.08)` + 文字 `#8a97a8`）；
  MA5/20/30/60 浅色 `#f0a020`/`#a06ee0`/`#4278ed`/`#0f9b8e`、
  深色 `#f5b94a`/`#c08ff0`/`#6fa3ff`/`#4fd1c5`；
  缩放控件同样是深浅两套（组件样式隔离，深色规则写在组件自身 wxss）；
- **不拥挤**：K 线画布 940rpx（价格 ≈ 200px + 成交量 ≈ 84px + MACD ≈ 113px，含面板间距），
  分时/五日 620rpx；左侧刻度留白按文字宽度自适应（54–120px），底部刻度首尾内收避免出界。

### 4.4 画布宽度链（组件容器的硬约束）

`quote-chart` 的画布是 `width: 100%`，宽度最终由**组件宿主节点**决定，因此下面两点不能改：

1. **组件根节点必须是带 `width: 100%` 的 `<view>`**（与 `kline-chart`、原 `minute-chart` 一致），
   不要把 `<canvas>` 直接作为组件根节点；
2. **承载组件的外层容器不能是行向 flex**：`.chart-wrap` 必须用「纵向 flex + 交叉轴 stretch」。
   行向 flex 的交叉轴是纵向，宿主节点会按内容（max-content）收缩宽度，画布 `width:100%`
   失去可解析的包含块宽度 → 画布宽度塌成 0（高度仍在），表现为**图表区域整块空白**。
   纵向 flex 的 `justify-content: center` 同时保留了加载 / 空态的水平与垂直居中。

自查：开发者工具 WXML 面板选中 `.quote-canvas`，宽度应等于面板内容宽（375 屏约 351px）而不是 0；
把 `.chart-wrap` 改回 `align-items: center`（行向）会立刻复现空白。

   仅**有色页沪主连与外盘金银铜、美元指数、部分兜底**会退化为「该周期暂无数据」。

5. **美股五日的时间口径**：腾讯 `dayus` 返回交易所本地时钟（09:30-16:00 ET），
