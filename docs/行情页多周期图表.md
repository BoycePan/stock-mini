# 行情页多周期图表（分时 / 日K / 周K / 月K / 年K + 成交量 + MACD）

> 需求：`packageQuote/pages/minute/index` 的分时图增加周期 TAB（分时 / 日K / 周K / 月K / 年K），
> 成交量下方增加 MACD，**只用国内接口**，覆盖全部标的（没有该周期数据源时 TAB 置灰提示），
> 布局与配色在浅色 / 深色两套主题下都要清晰、不拥挤。
>
> 落地：TAB 切换复用同一张画布（`packageQuote/components/quote-chart`），
> 分时走东财 `trends2`（`ndays=1`），
> 日/周/月 K 走「东财（板块指数 / 国际指数）→ 腾讯 → 新浪」兜底链，年 K 由月 K 聚合（国内无年 K 直连源）。
>
> **2026-09-15 补齐**：原先 68 个标的（30 个 A股板块 + 30 个美股板块 + 8 个指数 / 交叉汇率）只有分时、
> 没有日K（TAB 置灰）。本次接入东财历史 K 线（`push2his`）、代理股均值合成与交叉汇率合成后，
> 分时配置里的**全部 116 个标的**都有日/周/月/年 K（覆盖度由单测强制校验）。
>
> **2026-09-17 移除五日周期**：原「五日」TAB（多日分钟线）连同数据层一并删除，
> 周期 TAB 收敛为**分时 / 日K / 周K / 月K / 年K 五个**（见下「已移除：五日周期」）。

### 已移除：五日周期（多日分钟线，2026-09-17）

`utils/minute-session.ts` 的分日切分（`splitMinuteDays` / `minutePointDate` / `minuteDayLabel`）、

以及 `quote-chart` 的 `fiveDay` 模式与 `tests/five-day.test.ts`。

保留一条上游实测结论（后续若要重启五日可直接复用）：

| 端点 | `ndays=5` 实测 | 结论 |
| --- | --- | --- |
| `push2delay.eastmoney.com` / `push2.eastmoney.com` `api/qt/stock/trends2/get` | `1.000001` 回 241 行（当日）；`100.DJIA` / `105.NVDA` 回当日 391 行（`ndays=1` 与 `ndays=5` 逐字节同长度） | **两个节点都静默忽略 ndays**，只回当日 |
| `push2his.eastmoney.com/api/qt/stock/trends2/get` | `1.000001` 回 1205 行 / 5 个自然日；`100.DJIA` 回 1596 行 / 6 个北京日期 | 支持 `ndays=5`，但小程序环境被风控重置（504 / 0 字节），**不可依赖** |

### 东财 K 线（`push2his`）：补板块指数与国际指数，但不作为通用首选

东财历史 K 线只有 `push2his.eastmoney.com` / `82.push2his.eastmoney.com` 节点提供：
延迟节点与实时节点都明确返回空数据（2026-09-15 复测 `push2delay` / `push2` 对 `90.BK1134`
均返回 `{"data":{"code":"BK1134",…,"klines":[]}}`，对 `1.600519` 返回 `rc:102` + `data:null`）。

`push2his` 的特点（2026-09-15 复测）：

- 正常浏览器 / 服务端出口（国内 IP）请求**稳定可用**：`90.BK1134` 返回完整板块日线，
  `251.SOX` / `100.N225` / `47.800005` 等腾讯与新浪都没有的标的也都有数据；
- 对**异常流量**会直接空响应（连接重置 / `Empty reply`）：本次复测从海外出口 IP
  连续请求即被掐断（`code=000 size=0`），而同一时刻 `push2delay` 正常返回 200。
  这也解释了 `docs/魔方板块分析/魔方板块-接口文档.md` 里抓包时 75 次 999 的现象
  （抓包代理的出口 IP 与小程序客户端行为不同，并非接口本身不可用）。

因此接入策略是**只在没有腾讯 / 新浪源时才走东财**（`config/kline.ts` 只给板块指数、国际指数、
平均股价登记 `em`），并保留一个备用节点轮换：

- 好处：已有可靠源的标的（A股 / 港股 / 日韩个股 / 美股 / 期货 / 外汇）不会被东财风控拖慢
  （东财失败要等一次超时才降级，本次不引入这个等待）；
- 代价：A股板块（`BKxxxx`）只有东财一个源 → 该节点不可用时，板块 K 线 TAB 回到
  「该周期暂无数据」空态（分时用的是 `push2delay`，不受影响）。

**需要后端接口来兜底吗**：本次不需要。若线上真机验证发现 `push2his` 在小程序内被拦，
再让后端加一个 `GET /api/v1/sector/em-board/{code}/klines` 转发即可（服务端出口不受该风控影响），
前端只需把 `api/kline.ts` 的东财取数换成后端路径。

### 合成标的（无独立指数，按已有代理 / 两腿合成）

| 标的 | 合成方式 | 口径 |
| --- | --- | --- |
| 美股时段行业板块 `us-BKxxxx`（30 个） | 各代理股日线按**公共交易日首个交易日收盘**归一化到 100 → 逐日取等权均值 | 与卡片展示的「代理股涨跌幅均值」、分时合成完全一致 |
| 交叉汇率 `CNYKRW` / `CNYJPY` | 两腿日线逐日相除（`USDKRW ÷ USDCNH`、`USDJPY ÷ USDCNH`） | 与分时的合成口径一致（离岸口径，note 提示价差） |

细节：

- 合成只有**日线**，周 / 月 / 年一律由日线聚合（东财 `klt` 也只有日 / 周 / 月）；
- 代理股里单只失败自动跳过（部分可用即合成），全部失败才判空态；
- 只取**全部可用代理股都有数据**的交易日，避免某只代理停牌当日把均值带偏；
- 合成量无口径（恒 0）→ `quote-chart` 检测到全 0 自动隐藏成交量面板，MACD 仍按收盘价计算；
- 腿数据的取数结果带 60s 缓存（`#leg|` 前缀与真实卡片 code 隔离），
  切换日 / 周 / 月 TAB 不会重复拉取新浪外汇的全量历史。

### 为什么不用腾讯 app 侧 K 线（`proxy.finance.qq.com`）

`docs/数据源备用接口参考文档.txt`（抓包）里有 `proxy.finance.qq.com/cgi/cgi-bin/stockinfoquery/kline/app/get`
（`ktype=day|week|month|**year**`，`nodes[]` 结构，**原生支持年 K**），但该接口带
`fskey` / `appid` / `openid` / `check` 等签名参数：实测**不带签名与照搬抓包签名均无响应**
（返回空 body，疑似按小程序 appid + 会话签名校验），不可作为稳定依赖，故未纳入。

## 三、图表设计（三块面板，有则展示）

```
┌──────────────────────────────────────────────┐
│ MA5  MA20  MA30  MA60（K线）← 图例行（自适应） │
│ 价格主图：网格 + 左侧刻度（分时中线为 0%）     │
│   分时：分段着色价格线 + 均价线（黄）           │
│   K 线：蜡烛 + MA5/20/30/60 + 最新价虚线标签    │
├──────────────────────────────────────────────┤
│ 成交量：柱按涨跌分色（K线实色、分时半透明）      │
├──────────────────────────────────────────────┤
│ MACD(12,26,9)：零轴居中 + 红绿柱 + DIF/DEA 双线 │
└──────────────────────────────────────────────┘
   [ 30 / 320 根 ]                    [+][−][‹][›]
   ↑ K 线模式下的窗口文案与缩放 / 平移控件
```

- **顺序与可见性**：价格 → 成交量 → MACD；成交量全为 0（外汇等）时整块隐藏，
  K 线不足 34 根（`slow + signal - 1`）时隐藏 MACD 面板，**隐藏后空闲高度自动给价格主图**，
  不会留下空白条；分时不出 MACD（同一张图内没有 K 线序列，MACD 无意义）；
- **K 线可见窗口（默认 30 根）**：日/周/月/年 K 不再一次画几百根（又卡又糊），
  默认只画**最近 30 根**（板块 / 个股详情页的 `kline-chart` 同步如此），改窗口只有按钮 + 双指：
  1. **`‹` / `›`：轻点移动 1 根**，长按约 400ms 起连发（每 80ms 一次，步长每 10 次加 1 根：
     1 → 2 → 3 …），长历史几秒翻到头；贴到首 / 尾后按钮置灰，左侧显示「当前根数 / 全量根数」；
  2. `+` / `−` 缩放：根数 ×0.7 / ÷0.7（右端锚定，窗口停在最新一根时始终贴着最新）；
  3. **双指捏合**缩放：指距放大 = 根数变少，锚点定住两指中点那一根（手感与系统缩放一致），
     指距变化 <2% 的死区忽略，避免手指抖动把窗口来回抖。
  **单指只用于查看数据**：按下 / 滑动都只把十字光标移到手指位置（读数不断线），
  **不会拖动 K 线**——避免「想看一下数值却把图拖走」；分时没有窗口，行为同样只有十字光标。
  **上下限**（`utils/kline-viewport.ts`）：根数 ∈ [10 根, 全量]，`viewEnd` ∈ [0, 总数-1]，
  任何路径都经 `clampViewport` 夹回 —— 既不会放大到一根都看不见，也不会缩到窗口比数据还长、
  更不会挪出数据范围。切 TAB / 重新取数时窗口复位到最新 30 根（主题切换保留你调好的窗口）。
  **均线与 MACD 一律在全量 K 线上算完再按窗口切片**（`buildKlineView`）：
  若只在 30 根窗口内计算，MA60 会因为预热不足直接画不出来；
- **均线周期**：`utils/kline.ts` 的 `KLINE_MA_PERIODS = [5, 20, 30, 60]` 是单一数据源，
  屏幕 K 线图（行情页与板块 / 个股详情页）与分享海报（`utils/kline-poster.ts`）共用；
  图例带数值并自适应——放不下先降字号（10px → 9px），再放不下只留周期名
  （`utils/kline-legend.ts`），避免四条均线的数值互相叠压；
- **纵轴范围**：K 线的价格上下界把可见窗口内的均线一并算进去
  （`computeKlineRange(klines, 0.06, maSeries)`）——窗口只有 30 根时 MA60 会落在
  K 线高低点之外（强趋势段），不并入就会被画到价格面板外、压住成交量面板；
  实测 `usDJI` / `sh600519` / `NVDA` 日 K 的 30 根窗口都会出现这种情况；
  另外全为正价时下界夹到 0，避免长期前复权序列（年 K 由月 K 聚合，跨度数百倍）
  出现「-135.80」这类不存在的价格刻度；
- **分时的均价线（黄）**：A股 / 港股按真实累计成交额推算（额 ÷ 量，手 / 股两种量纲自动识别）；
  指数（无量价换算关系）与美股代理合成等无累计额口径的源退化为**成交量加权近似**，
  即当日成交重心，页面口径提示中已注明为近似值；完全无量的标的不出均价线；
- **十字光标**：竖线贯穿三块面板，横线在价格面板，信息框按模式给出不同字段
  （分时：时间/价格/涨跌/均价/量；K 线：时间/开/高/低/收/涨跌/量），
  成交量与 MACD 顶行数值随选中的那根实时切换（同花顺式）；
- **配色**：涨 `#eb514d` / 跌 `#20a66a` 两主题一致；网格、文字、零轴、信息框底色随主题切换
  （浅色网格 `rgba(20,32,51,0.08)` + 文字 `#718096`；深色网格 `rgba(255,255,255,0.08)` + 文字 `#8a97a8`）；
  MA5/20/30/60 浅色 `#f0a020`/`#a06ee0`/`#4278ed`/`#0f9b8e`、
  深色 `#f5b94a`/`#c08ff0`/`#6fa3ff`/`#4fd1c5`；
  缩放控件同样是深浅两套（组件样式隔离，深色规则写在组件自身 wxss）；
- **不拥挤**：K 线画布 940rpx（价格 ≈ 200px + 成交量 ≈ 84px + MACD ≈ 113px，含面板间距），
  分时 620rpx；左侧刻度留白按文字宽度自适应（54–120px），底部刻度首尾内收避免出界。

### 4.4 画布宽度链（组件容器的硬约束）

`quote-chart` 的画布是 `width: 100%`，宽度最终由**组件宿主节点**决定，因此下面两点不能改：

1. **组件根节点必须是带 `width: 100%` 的 `<view>`**（与 `kline-chart`、原 `minute-chart` 一致），
   不要把 `<canvas>` 直接作为组件根节点；
2. **承载组件的外层容器不能是行向 flex**：`.chart-wrap` 必须用「纵向 flex + 交叉轴 stretch」。
   行向 flex 的交叉轴是纵向，宿主节点会按内容（max-content）收缩宽度，画布 `width:100%`
   失去可解析的包含块宽度 → 画布宽度塌成 0（高度仍在），表现为**图表区域整块空白**。
   纵向 flex 的 `justify-content: center` 同时保留了加载 / 空态的水平与垂直居中。

自查：开发者工具 WXML 面板选中 `.quote-canvas`，宽度应等于面板内容宽（375 屏约 351px）而不是 0；
把 `.chart-wrap` 改回 `align-items: center`（行向）会立刻复现空白。
